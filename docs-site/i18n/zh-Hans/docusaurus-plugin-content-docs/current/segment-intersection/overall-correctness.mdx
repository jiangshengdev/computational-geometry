[第八章](./complete-sweep.mdx)让我们跟完了一次混合扫描。现在离开那份具体输入：**为什么换成任意允许的输入，整条过程仍然成立？** 前面各章已经给出了局部理由；本章要说明这些理由按什么次序接上，才能从开始一直保证到结束。

## 第一节：把已有结论接成完整证明 {/* #premises */}

输入是有限份闭线段，坐标都是精确有理数。允许共端点、端点落在别的线段内部、多线共点、同横坐标事件、重叠、竖直线段和零长度的点输入。没有输入、只有一份输入或全部互不相交，也在讨论范围内。

目标沿用[第一章的结果约定](./what-we-compute.mdx)：每个相交的原始无序输入对，恰好留下一个完整交集，或者是点，或者是一段非零长度的闭区间；不相交的对没有结果。完全重合、端点反向的输入仍各有身份。「无序」只表示交换同一对的两份输入不产生新的一对，不表示合并位置相同的不同输入。

先确认扫描使用的坐标。没有非零竖直输入时沿用原坐标；否则按[第七章](./vertical-segments.mdx)选安全剪切系数，并统一变换全部输入，包括点。复用[保序结论](./shear/order.mdx)和[非竖直条件](./shear/special-cases.mdx)：原先不同横坐标的真实事件不颠倒，原先同列的不同位置按高度分开，变换后的非零输入都不竖直。这里要求的是已证明安全的系数，不能随意选一个小数。变换[保持完整交集](./shear/intersection.mdx)，所以可以先证明新坐标中的扫描，再还原结果。

以下的横坐标、纵坐标都指**实际用于扫描的坐标**。按[第六章的完整次序](./same-x-events.mdx#第一节先到左边同列再从低到高)，先比较横坐标，再在同列内比较纵坐标；两者都相同才是同一位置。无须剪切时仍可能同列，因此不能删掉第二层比较。[第三章的精确判断](./exact-predicates.mdx#第六节让求交结果继续参与判断)保证求交、同点识别、范围和次序比较使用同一份精确值。剪切负责满足几何条件，精确计算负责忠实判断；两者不能互相替代。

后面的连接使用这些已有结论：

| 已有结论与条件 | 本章用在何处 |
| --- | --- |
| [没有事件就不换序](./why-neighbors-proof.mdx#没有事件就不会改变顺序)：成员持续存在，期间没有端点或交点；同线成员按[组](./overlapping-segments.mdx#第七节把顺序与事件发现的理由接到组上)处理 | 从上一次处理后的状态走到下一处之前 |
| [找齐同点参与者](./same-point-events.mdx#怎样找齐旧活动参与者)：旧状态正确，先找经过当前位置的完整块，再合并该处端点和点输入；重叠时展开[经过此处的组成员](./overlapping-segments.mdx#第三节外部穿越只展开跨组对) | 一次到站不只报告负责发现位置的那一对 |
| [同线唯一报告与当前覆盖](./overlapping-segments.mdx#第二节新成员加入时就报告完整交集)：仅使用已开始、尚未在自身结束事件退出的成员，保留闭端点 | 连接累计结果、组成员与未来检查 |
| [同列状态保持](./same-x-events.mdx#第四节中间状态为什么还能按高度查找)及[完整未来比较](./same-x-events.mdx#第六节完整的未来次序怎样接到事件发现)：逐点从低到高处理，只更新当前块 | 不把整列提前变成右侧顺序 |
| [组交点发现](./overlapping-segments.mdx#没有端点提示时怎样保证来得及预约)及其[同列连接](./same-x-events.mdx#同列低处的更新会不会妨碍高处被发现)：此前状态正确，新邻接检查和覆盖延长补检都已执行，真实未来位置保留 | 保证下一处需要到达的位置来得及登记 |

这些结论不是在假定「整个过程已经正确」以后一起使用。我们只从最初的空状态起步：第三节先回答**如果此前正确，且这次确实到达下一处，那么处理后怎样继续正确**；第四节再说明为什么不会跳过这下一处。

## 第二节：扫描开始时，正确性从哪里起步 {/* #initialization */}

先说清楚每次处理结束后保留的记录。「当前」指已经完成这一个位置、尚未处理下一个位置的时刻；不是只给出横坐标而忽略同列进度。

| 记录 | 要保持的含义 |
| --- | --- |
| 活动成员 | 非零输入从自己的开始事件加入，到自己的结束事件完成报告后退出。尚未开始者不活动；点输入只参加自己的位置 |
| 组顺序 | 当前非空同线组从下到上排列。同列低处已处理的块取右侧顺序，高处未处理的块保留左侧顺序；整列高度仍不递减 |
| 当前覆盖 | 每个非空组只根据当前成员计算最远右端；固定的同线归属不等于一直有覆盖 |
| 待处理清单 | 所有尚未取出的端点位置，加上已确认的真实未来交点；同一位置一份，所带输入身份全部保留 |
| 累计结果 | 已经到达各自报告时机的输入对的完整交集，每对一次；不是扫描位置左侧所有几何部分的合集 |

覆盖的等号尤其需要保留。设当前列横坐标为 $t$，成员 $i$ 的开始、结束横坐标分别为 $\ell_i,r_i$。在同列处理的中途，仍保留的旧成员可以满足

$$
\ell_i\le t\le r_i.
$$

这里的 $i$ 是输入身份，$\ell_i,r_i$ 只是它的两个边界。高处尚未处理的结束者可能有 $r_i=t$；不能因为低处已处理，就要求整列所有成员都满足 $t<r_i$。每个非空组的当前最远右端，是这些成员的 $r_i$ 中最大者；只有整列处理完，留下的成员才都继续到该列右侧。这个区别沿用[第六章的覆盖等号](./same-x-events.mdx#中间状态中的覆盖等号怎样处理)。

初始化时，尚未处理任何位置。活动成员为空，因此没有非空组、组顺序或覆盖；没有发生任何报告时机，因此结果为空。这些空记录恰好符合上表，不需要假定任何交点已知。

端点来自输入本身：每份非零线段的两端预先登记，点输入登记它自己的位置；位置相同就合并位置记录，保留所有相关身份。由精确次序把这些位置排好。**没有预先枚举全部交点。** 未来交点要靠后续检查发现。

为什么从这个起点能走出第一步？如果输入非空，就有最早端点。任何非空交集上的位置都不早于参与输入的开始位置；在已经满足非竖直条件的坐标中，非零线段的内部严格在开始端点右边，点输入只在自己的位置。因此最早的真实事件必定是已登记的端点位置。到它之前没有活动成员，也没有应报告的输入对。输入为空时则连第一步都不需要，结果直接为空。

## 第三节：一次处理怎样保持正确 {/* #preservation */}

把这次位置记为 $P$。现在只作两个假设：**严格早于 $P$ 的真实事件已依次正确处理；$P$ 确实是下一处应处理的位置。** 不假定更晚的交点都已登记。

### 从此前状态找齐这次参与者 {/* #participants */}

从上一次处理后到 $P$ 之前，没有跳过别的端点或交点。因此已有的成员与组顺序保证仍可用。若 $P$ 在同一列更高处，则用的是低处已经更新、高处尚未更新的中间状态；[第六章](./same-x-events.mdx#第四节中间状态为什么还能按高度查找)已经保证这种状态仍能按高度找到完整相遇块。

于是，[同点收集结论](./same-point-events.mdx#怎样找齐旧活动参与者)可在这里使用：找齐经过 $P$ 的旧活动组及其当前成员，再加入在 $P$ 开始的输入和位于 $P$ 的点输入。结束者还没有退出，所以共端点接触不会丢掉；端点落在内部时，内部穿过者来自旧块；多线共点时，整块都收齐，不受最初预约对的数量限制。点输入不属于持续活动顺序，但端点清单给出了它在这里的身份。

### 让这次报告接上此前结果 {/* #reporting */}

按已有规则，把不同原始输入的无序对分成三类：

| 类别 | 本次何时报告，依据是什么 |
| --- | --- |
| 两份非零输入在同一直线上 | 后开始的成员加入时，与该组仍包含当前位置的成员配对；同点开始者按固定身份顺序逐一加入。使用[同线唯一报告结论](./overlapping-segments.mdx#为什么每个相交同线输入对恰好报告一次)，留下完整闭交集 |
| 两份非零输入属于不同组 | 在它们共同经过的 $P$，展开全部跨组成员对。不同直线至多有一个交点，因此该点就是这些对的完整交集；组内对不在这里再次展开 |
| 至少一份为点输入 | 在该点位置，与这里所有其他参与者配对；点与点也按无序对各取一次。使用[点输入规则](./same-point-events.mdx#第五节零长度输入参与这一次不留到右侧)，交集就是这个点 |

每对要么含点，要么两份都非零；后一种的所在直线要么相同，要么不同。因此三类覆盖全部可能，且一对不能同时属于两类。这里的分类排除了跨类重复；各类内部的唯一报告由表中规则保证。身份不同但形状相同的输入仍逐对处理。

此前结果已经正确。这次只加入报告时机恰好在 $P$ 的对，收集完整且没有混入不经过此处的成员，所以没有漏掉本次应报告的对，也没有增加空交集。此前已报告的对不会因再次经过一个位置而重报：同线对只在较晚的加入时报告，跨组对只有一个交点，含点对只在点的唯一位置报告。

特别是，同线对现在报告的是**完整区间**，其终点可以在 $P$ 的右边。原始端点已知，第三章的[完整共线交集](./exact-predicates.mdx#第四节共线时从原端点选出完整区间)已经确定这段范围；不必等扫描走到区间末端。这样延伸到未来的结果，正符合第二节按「报告时机」表述的保证。

### 更新后继续保留下一次所需的条件 {/* #update */}

报告完成后，才让在 $P$ 结束的成员退出；点输入也不继续活动。留下穿过者和非零开始者，并按[当前块的右侧顺序](./same-x-events.mdx#第五节为什么只更新当前块)更新。块外不在 $P$ 增删或交叉，仍保留原状态。于是低处已处理、高处未处理的约定继续成立；高处的结束者不会被提前删除或换序。

随后按当前成员重新确定覆盖。加入者若延长最远右端，就执行[覆盖延长补检](./overlapping-segments.mdx#第五节邻居没变覆盖延长也要补检)，即使邻居名字没变也不能跳过。组空时退出活动顺序；以后同线成员重新开始时再加入，不能借它尚未开始的部分填平过去的空隙。这里分别使用[空组结论](./overlapping-segments.mdx#第六节组空了以后不能跨过空隙继续覆盖)及[同列覆盖规则](./same-x-events.mdx#覆盖延长和空组仍按自己的位置处理)。

更新形成的新邻接也全部检查：新块内部、它与外侧的边界，以及块为空时连接两侧的邻接，按[已有分类](./same-point-events.mdx#第七节更新以后检查哪些邻接)逐一覆盖。检查先确认真实的闭范围交集，再按完整位置次序判断是否严格晚于 $P$。因此同列高处仍可属于未来，而当前位置和过去的位置不会重新加入。已经登记的真实未来位置继续保留，重复发现只合并位置，不合并输入对身份。

这样，一次处理既延续了成员、顺序、覆盖和结果的保证，也执行了下一次发现所依赖的两种检查：**新邻接检查，以及覆盖延长补检**。还剩一个问题：我们凭什么确信刚才假设的「下一处」不会被清单跳过？

## 第四节：为什么能一直走到该去的位置 {/* #discovery */}

这里承接的是已有发现证明，不重新证明交点前为什么出现邻接。需要使用的是[第五章的组发现结论](./overlapping-segments.mdx#没有端点提示时怎样保证来得及预约)和[第六章的同列版本](./same-x-events.mdx#同列低处的更新会不会妨碍高处被发现)：**在此前事件正确处理、两类检查执行且真实预约保留的条件下，一个没有端点提示的真实组交点，会在到达它之前被登记。** 它要求有当前成员真实覆盖交点，不能使用整条支撑直线或未开始成员代替覆盖。

现在从一个已正确处理的边界向后看。如果还有真实事件，就取其中按完整次序最早的位置，记为 $Q$。这是证明中从实际几何位置里选一个对象，不是让算法预先算出全部交点。位置只有有限个；其来源在下一节连接终止理由时列出。

1. 若 $Q$ 带有端点或点输入，初始化已经登记它。它尚未处理，所以记录还在。
2. 否则，$Q$ 只能是不同组非零输入的真实交点。严格早于 $Q$ 的事件都在已正确处理的部分；第三节保证这些处理中两类检查已经执行。因此上面的发现结论满足前提，$Q$ 已经登记。这里也包括邻接一直不变、后来覆盖才够到 $Q$ 的情形。
3. 清单只含真实端点和经过范围确认的真实交点，且不含已处理位置。因此它不可能还含一个比 $Q$ 更早的未处理位置；否则 $Q$ 就不是所选的最早者。又因为清单含有 $Q$，取最小位置就一定取到 $Q$。

这三步把下一次处理所需的条件交给了第三节。起点由第二节建立；从起点走到第一处，处理后仍正确；再从这个新边界使用相同连接，走到下一处并正确处理。每次只借助此前已经建立的状态，没有借用后面的处理结果。

也不需要声称「任意时刻全部未来交点都已在清单」。有些交点要等新邻接形成或覆盖延长才能发现。我们需要、并已接通的只是：**只要还有下一处真实事件，就会及时登记并取到它。** 清单的位置合并保证只到站一次；到站后仍由第三节收齐参与者，报告各个不同的原始输入对。

## 第五节：清单为空，为什么答案已经完整 {/* #completion */}

第二章已经用[有限位置、保留预约和按序取出](./why-neighbors-proof.mdx#从检查一直追到报告)说明不会永远停在某个交点之前。现在把这些条件接到完整输入上。

输入有限，所以端点位置有限，点输入的位置也在其中。非零输入的所在直线也只有有限条；每两条不同直线至多有一个交点，只有落在实际输入闭范围内的点才需要处理。因此真实事件位置有限。重叠虽然含有无穷多个公共点，却在加入时作为一个完整区间报告，不把区间里的每个点列为事件。

每次处理只涉及有限份成员、输入对和邻接检查。处理完就移去当前位置；精确的严格未来比较禁止它重新加入，同位置合并又禁止清单保存多份相同位置。因此每次完成一个此前未完成的真实位置，只能执行有限次，扫描会结束。

**终止还不等于答案完整；这里必须接上第四节。** 如果结束时还有未处理的真实事件，就能选出下一处，第四节保证它已经在清单中，与清单为空冲突。因此全部真实事件都已到达，而第三节已将正确性保持到最后一个边界。

再按各对的报告时机核对最终保证：

- 同线非零相交对：后开始者的端点已经处理，同点开始也已按固定身份顺序加入，所以唯一报告时机已发生，得到的是完整闭交集。
- 不同组非零相交对：唯一交点已经处理，完整相遇块展开了这一对，得到该点。
- 含点输入的相交对：点的位置已经处理，在完整参与者中配过这一对，得到该点。

第三节已说明这三类互斥且穷尽，类内不会重复，也不会报告空交集。现在又知道所有相交对的报告时机都已发生，于是统一得到：**每个相交原始无序输入对恰有一个完整交集，不漏、不多报、不重复。** 多个输入对可以共享同一个点结果的位置；清单只处理一个位置，不会删去这些不同的对。

没有输入时，空结果已经完整。只有一份输入时，虽然可能处理它的端点，却没有两份不同输入可配对；结果仍为空。全部互不相交时，各次报告都找不到非空输入对，也得到空结果。前面的推进与结束理由均不要求至少存在一个交点。

最后回到原始坐标。没有剪切时结果已经在原坐标中。使用剪切时，把扫描坐标记为 $(x',y')$，原坐标记为 $(x,y)$，统一系数仍记为 $s$。复用[逆变换](./shear/intuition.mdx#从新坐标求回原坐标)：

$$
x=x'-sy',\qquad y=y'.
$$

按[交集保持结论](./shear/intersection.mdx)，一个点对应回原来的点，一段完整闭交集对应回两端逆变换后的**整段**闭交集，而不是两个点结果。变换一一对应，且原始输入身份始终保留，所以既不会制造额外相交对，也不会合并重复或反向输入的身份。新坐标中的最终保证就转回了第一节规定的原问题。

从空状态起步，每次到达必要位置并保持保证，有限次后到达全部报告时机，再恢复原坐标，这条证明到此闭合。维护这些记录与精确数值究竟需要多少工作，留给第十章讨论。

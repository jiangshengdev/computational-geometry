If someone gives you several line segments and asks where they intersect, what would you do? A direct approach is to take two segments, check whether they share any part, and then move on to another pair until every pair of distinct inputs has been checked.

This approach is easy to think of. Before looking for a method that does less work, however, we need to clarify two things: **what do we check each time, and what result should we keep?**

This is Chapter 1 of the Bentley–Ottmann segment intersection series. We first establish the problem and a baseline method. The next chapter studies how a sweep line can reduce the number of segment pairs that need attention.

## Each Input Has Its Own Identity {/* #一份输入有一个身份 */}

A segment can be described by two endpoints. For example, the segment with endpoints $(0,0)$ and $(4,0)$ is the part of the horizontal axis from $0$ to $4$.

The segments we discuss **include both endpoints**. Such a segment is called a “closed segment.” Thus, both $(0,0)$ and $(4,0)$ lie on this segment. A line extends indefinitely in both directions, but a segment has a limited extent: $(5,0)$ lies on the line extending this segment, but not on the segment itself. To review how an equation and coordinate bounds work together to describe a segment, see [Writing a Line Equation from Two Endpoints](./line-equation.mdx).

The two endpoints may also be the same. If both are $(2,0)$, the input contains only the point $(2,0)$ and has length $0$. We accept inputs like this too.

Now number the inputs: input $1$, input $2$, input $3$, and so on. A number distinguishes one input from another; it does not describe the segment's length or location.

Suppose we have the following three inputs. The figures label them $\teachBlue{S_1}$, $\teachOrange{S_2}$, and $\teachViolet{S_3}$; the subscript is the input number:

| Input number | Endpoints |
| --- | --- |
| $1$ | $(0,0)$ and $(4,0)$ |
| $2$ | $(0,0)$ and $(4,0)$ |
| $3$ | $(4,0)$ and $(0,0)$ |

They occupy exactly the same geometric location. The third input merely lists its endpoints in reverse order, which does not change the points it contains. Nevertheless, these are **three inputs**. We must not silently merge them into one just because their drawings coincide.

We use “input pair $1$ and $2$” to mean the two inputs numbered $1$ and $2$. This is the same pair as “input pair $2$ and $1$,” because reversing the order of checking does not change their common part. This is called an “unordered input pair.” We choose two distinct inputs and never check an input against itself.

## What Can Two Segments Have in Common? {/* #两条线段的公共部分是什么 */}

All points belonging to both segments together form their “intersection.” If they have no common point, their intersection is empty.

Fix a segment $\teachBlue{A}$ from $(0,0)$ to $(4,0)$. Every point on it satisfies $y=0$, and its horizontal coordinate ranges from $0$ to $4$, including both ends. In each example below, choose one other segment and compare it with $A$ alone.

In the figures, $\teachOrange{B}$ labels the other input, and $\teachViolet{A\cap B}$ denotes the intersection of the two inputs. The symbol $\cap$ is read as “intersection.” When there is no common point, we denote the empty intersection by $\varnothing$.

### No Common Point: An Empty Intersection {/* #没有公共点空交集 */}

Let the other segment run from $(0,1)$ to $(4,1)$. All its points satisfy $y=1$, whereas all points on $A$ satisfy $y=0$. A point's vertical coordinate cannot be both $0$ and $1$, so the segments have no common point.

We have checked this input pair, but it **produces no intersection result record**.

### Exactly One Common Point: A Point Intersection {/* #只有一个公共点点交集 */}

Replace the other segment with the vertical segment from $(2,-1)$ to $(2,1)$. Every point on it satisfies $x=2$. A common point must also lie on $A$, so its vertical coordinate must be $0$.

These two conditions leave only $(2,0)$. Its horizontal coordinate $2$ is between $0$ and $4$, and its vertical coordinate $0$ is between $-1$ and $1$, so it really lies on both segments. Their intersection is this one point.

Touching at an endpoint also counts as intersecting. For example, replace the other segment with the horizontal segment from $(4,0)$ to $(6,0)$. A common point's horizontal coordinate can be neither greater than $4$ nor less than $4$, so it must equal $4$. Both segments include this endpoint, making their intersection $(4,0)$.

If it contains only $(5,0)$, the point is outside the bounds of $A$, so the intersection is empty. Two point inputs have a common point only when their locations are the same.

### A Shared Segment: An Overlap Interval {/* #有一段公共部分重叠区间 */}

Now let segment $B$ run from $(2,0)$ to $(6,0)$. Both it and $A$ lie on the horizontal axis.

A common point must satisfy both

$$
\teachBlue{0}\le x\le\teachBlue{4},\qquad \teachOrange{2}\le x\le\teachOrange{6}.
$$

The second condition requires $x$ to be at least $2$, and the first requires it to be at most $4$. Thus a common point must satisfy $2\le x\le4$.

Conversely, take any number satisfying $2\le x\le4$. It is between $0$ and $4$ and also between $2$ and $6$. Therefore, $(x,0)$ belongs to both segments.

Together, these two directions show that the intersection is exactly the **complete closed interval** from $(2,0)$ to $(4,0)$, including both endpoints. Its length is $4-2=2$; it is not just a single point.

Reporting only two endpoint intersections would be wrong, because intermediate points such as $(3,0)$ also belong to the intersection. We use the interval's two endpoints to describe the entire common part, not to claim that only those two points are shared.

If we add a segment $C$ from $(3,-1)$ to $(3,1)$, it intersects $A$ and $B$ separately at $(3,0)$. These are results for two other input pairs. The points contained in $A$ and $B$ have not changed, so their intersection remains one complete interval from $(2,0)$ to $(4,0)$. It must not be split into two results at $(3,0)$.

## Why Can the Common Part Not Be Two Separate Pieces? {/* #为什么不会出现两段分开的公共部分 */}

We have seen empty intersections, points, and intervals of nonzero length. For closed segments, these cover every possibility.

First consider an input of length $0$. It contains only one point, so the common part can only be that point or the empty set; it cannot contain more points.

Now consider two segments of nonzero length. If the common part has no points, it is empty; if it has exactly one, it is a point intersection. What remains to show is this: **as soon as there are two distinct common points, the common part must be one complete segment.**

Call the two distinct common points $P$ and $Q$. Two distinct points determine one line. The lines containing both segments pass through $P$ and $Q$, so they are the same line.

If this line is not vertical, order its points by increasing horizontal coordinate. On this line, each horizontal coordinate corresponds to exactly one point. A segment extends continuously from one endpoint to the other, containing the points at every horizontal coordinate in between. If the line is vertical, use vertical coordinates instead; the reasoning is the same.

Compare the segments in this order. Let $L$ be the **later** of their two earlier endpoints, and let $R$ be the **earlier** of their two later endpoints.

No common point can precede $L$: it would be before the beginning of one segment. Nor can it follow $R$: it would be beyond the end of one segment. Thus every common point must lie between $L$ and $R$.

Conversely, every point from $L$ to $R$ is no earlier than either segment's earlier endpoint and no later than either segment's later endpoint. It therefore belongs to both segments. Since we already have two distinct common points, $L$ must precede $R$ and cannot coincide with it.

The common part is therefore exactly the complete closed interval of nonzero length from $L$ to $R$; there can be no gap inside it. This establishes all three possibilities. Here we use this fact to specify the shape of a result. Chapter 3 will explain how to compute the result from arbitrary endpoints.

## Record Both the Location and the Input Pair {/* #结果既要记位置也要记是哪一对 */}

Consider this small example with three inputs:

| Input number | Endpoints |
| --- | --- |
| $1$ | $(-1,0)$ and $(1,0)$ |
| $2$ | $(0,-1)$ and $(0,1)$ |
| $3$ | $(0,0)$ and $(0,0)$ |

Input $1$ lies on the horizontal axis, and input $2$ on the vertical axis. Their only common point is the origin $(0,0)$: a common point must satisfy both $x=0$ and $y=0$, and the origin is within both segments' endpoint bounds. Input $3$ contains only the origin, which also belongs to each of the first two segments. The results are therefore:

| Input pair | Complete intersection |
| --- | --- |
| $1$ and $2$ | Point $(0,0)$ |
| $1$ and $3$ | Point $(0,0)$ |
| $2$ and $3$ | Point $(0,0)$ |

Reading left to right and then top to bottom, the first three panels show inputs $1$, $2$, and $3$ separately, and the fourth places them together. All three contain the origin, but the results must still list the three input pairs separately, as in the table. The diamond still denotes the point input at the origin; we must not omit this input merely because it coincides with the intersection of the two segments.

There is only one geometric location but three intersecting input pairs, so we keep three results. Writing only “the origin” would not tell us which inputs intersect one another.

Return to the three coincident inputs at the start. They also form three pairs: $1$ and $2$, $1$ and $3$, and $2$ and $3$. Each input contains exactly the same points, so every pair's intersection is the complete interval from $(0,0)$ to $(4,0)$. Coinciding geometrically does not remove any input's identity.

We can therefore state our goal precisely: **find every unordered pair of original inputs with a nonempty intersection, and keep one result for each pair, recording the input pair and its complete intersection.**

## How Do We Check Every Pair Once? {/* #怎样把每一对都检查一遍 */}

Practice enumerating pairs with four inputs. Here we list only the pairs to check; their locations do not affect this enumeration.

| Current input | Pair only with higher-numbered inputs | Checks in this row |
| --- | --- | --- |
| $1$ | $1$ and $2$, $1$ and $3$, $1$ and $4$ | $3$ |
| $2$ | $2$ and $3$, $2$ and $4$ | $2$ |
| $3$ | $3$ and $4$ | $1$ |
| $4$ | No higher-numbered input | $0$ |

This checks $3+2+1=6$ pairs in total. For each pair, compute the intersection of its two inputs. Skip empty intersections, and record nonempty ones using the rules above.

The same method works for more inputs. Let us explain why it misses no pair and checks none twice.

**Why is no pair missed?** Take any two distinct inputs. One must have the smaller number and the other the larger. In the row for the smaller number, the rule pairs it with every larger number, so this pair must be checked. This applies to any two distinct inputs, regardless of their positions or whether they intersect.

**Why is no pair repeated?** A pair can occur only in the row for its smaller number. In the row for the larger number, the rule allows only still larger numbers; it never returns to the smaller one. In the smaller number's row, each larger number occurs only once. Thus the pair is checked exactly once in total.

The rule also avoids pairing an input with itself, because “higher-numbered” excludes an equal number. Provided each two-segment check computes the complete intersection correctly, the enumeration finds every intersecting input pair and keeps at most one result per pair. This is the baseline against which we can compare later algorithms.

## How Many Pairs Must Be Checked? {/* #一共需要检查多少对 */}

Let $n$ denote the number of original inputs. For example, with four inputs, $n=4$. We are counting inputs, so coincident inputs still count separately.

First suppose $n\ge2$. To count the distinct pairs, temporarily allow both possible orders. There are $n$ choices for the first input and then $n-1$ choices for a different second input. Each first choice has $n-1$ second choices, giving a total of

$$
n(n-1).
$$

But this counts each pair twice: for example, choosing $1$ then $2$, and choosing $2$ then $1$. Every pair of distinct inputs has exactly these two orders and no third; we need only one. Dividing the count by $2$ gives

$$
\frac{n(n-1)}{2}.
$$

We have already proved that the pairwise method checks each unordered input pair exactly once, so this is also its number of checks.

Substitute $n=4$, doing the subtraction in parentheses before multiplication and division:

$$
\frac{4(4-1)}{2}
=\frac{4\times3}{2}
=\frac{12}{2}
=6,
$$

which agrees with the $6$ pairs counted row by row in the table.

With no inputs or only one, we cannot choose two distinct inputs, so there are $0$ checks. The formula also gives $0\times(0-1)/2=0$ and $1\times(1-1)/2=0$. We establish these boundary cases first from “there is no pair to choose”; there is no need to interpret a negative number as a number of choices.

The number of checks grows quickly as the input count increases:

| Input count $n$ | Number of checks |
| --- | --- |
| $10$ | $10\times9/2=45$ |
| $100$ | $100\times99/2=4950$ |
| $1000$ | $1000\times999/2=499500$ |

Even if no two segments intersect, the pairwise method still checks this many pairs and produces no intersection results. Thus **the number of pairs checked** and **the number of pairs that actually intersect** are different quantities.

On the other hand, inputs for which every pair intersects do exist. For example, let all $n$ inputs occupy the same nonzero-length segment. Every pair's intersection is that entire segment, so the number of result records is also $n(n-1)/2$. If the results must be listed one by one, no method can avoid the work of outputting them.

Also, the number of checks is not the complete running time. Each check involves geometric decisions and calculations, and storing a result takes work too. With exact fractions, arithmetic can also become more expensive as the numbers get longer. This chapter counts only “how many pairs must be checked”; it does not claim that a check takes a fixed amount of real time. Later chapters will develop the full workload analysis.

## From the Baseline to a Sweep Line {/* #从基准方法走向扫描线 */}

We now have a precise goal: organize results by original input pair, retaining a point or one complete overlap interval for each intersecting pair. We also have a reliable baseline: checking pairs one by one misses none and repeats none, but checks $n(n-1)/2$ pairs regardless of how many actually intersect.

The next question is: **when many segments do not intersect, can we use their relative positions to check fewer pairs while still finding every result?**

Chapter 2, in [Part 1: The Sweep and Three Types of Events](./why-neighbors.mdx) and [Part 2: Why No Intersection Is Missed](./why-neighbors-proof.mdx), explores this question under explicit simplifying assumptions.

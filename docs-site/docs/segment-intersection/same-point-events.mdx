Chapter 2 handled starts, ends, and crossings of two segments separately. What happens when one segment ends exactly where another begins? Which action comes first? If other segments also pass through that position, is swapping only the pair that discovered the intersection enough?

This is Chapter 4 of the segment-intersection series. Starting with contact between just two inputs, we build one rule: **collect every same-point participant first, report all intersecting input pairs at this position, then update the active order, and finally check new neighbors.**

## Section 1: Why a shared endpoint must be reported before removal {/* #第一节共端点处为什么不能先删除 */}

We retain these teaching assumptions: nonzero segments are nonvertical, no two inputs have a positive-length overlap, and distinct event positions still have distinct horizontal coordinates. Other restrictions are lifted: several endpoints and segments may meet at one exact position, and zero-length point inputs are allowed. Collinear segments sharing only an endpoint are also allowed.

These conditions define this chapter's teaching scope, not the full algorithm's input restrictions. Overlaps, distinct positions with the same horizontal coordinate, and vertical segments are incorporated into the sweep in later chapters.

First take only two closed segments and name their common endpoint $P=(4,4)$:

| Input | Left endpoint | Right endpoint | Supporting line and range |
| --- | --- | --- | --- |
| $\teachBlue{A}$ | $(0,4)$ | $P=(4,4)$ | $y=4$, $0\le x\le4$ |
| $\teachOrange{B}$ | $P=(4,4)$ | $(8,8)$ | $y=x$, $4\le x\le8$ |

All figures here are teaching diagrams arranged around the explanation, not real execution traces. Each has an original size of 320 × 260 and wraps onto a new row if space is limited. Read left to right, then top to bottom. One grid square is one coordinate unit, and $O$ is the origin. The table and text specify the exact endpoints and ranges.

By Chapter 1's [convention that a closed segment contains its endpoints](./what-we-compute.mdx#一份输入有一个身份), $P$ belongs to both $A,B$. Then apply Chapter 3's [unique-candidate and closed-range checks](./exact-predicates.mdx#分母不为零算出候选点再检查范围): their supporting lines intersect at $P$, and $4$ belongs to both closed ranges, so this pair's complete intersection is $P$.

The active order immediately left of $P$ contains only $A$, and immediately right only $B$. If “$A$ ends” means immediately forgetting $A$, before handling “$B$ starts,” one input is missing when pairs are formed, and the endpoint contact of $A,B$ is missed.

The correct order is to retain $A$'s identity for this event, include $B$ as a participant, and report intersection $P$ for input pair $A,B$. Only then does $A$ leave and $B$ enter the subsequent active order. **Not extending farther right does not mean failing to contain the current closed endpoint.**

This reasoning does not depend on the two lines' directions in the figure. Any input ending here still contains this point. If other participants are present, pairing at the current position must be completed before discarding ending members.

## Section 2: An endpoint inside another input needs participants beyond the list {/* #第二节端点落在内部清单之外还有谁 */}

Keep $B$ and pair it only with a new input $\teachViolet{C}$ for this example; omit $A$ for now. $C$ runs from $(1,7)$ to $(9,-1)$ on $y=8-x$, with range $1\le x\le9$. Substituting $x=4$ gives $y=8-4=4$, and $1<4<9$, so $P$ lies strictly inside $C$.

  panels={['An endpoint lies inside another segment: B starts at P=(4,4); C, from (1,7) to (9,-1), passes strictly through P. Only C exists to the left; the right-side bottom-to-top order is C, B.']}

$B$'s start is on the pending list from the beginning, but merely reading “$B$ starts” has not located $C$. Pairing only the endpoint inputs named in the list would again miss a result.

At the event's horizontal coordinate, reuse Chapter 3's [exact height comparison at one position](./exact-predicates.mdx#第九节把直线方程接到活动顺序). Compute the heights of old active segments still covering $x=4$. $C$ has height $4$, equal to $P$'s vertical coordinate, so it also passes through $P$ and must participate alongside starting input $B$. The intersection result is point $P$ for pair $B,C$.

The new rule is: **after reading an endpoint, also find old active members at the same height.** A segment is not irrelevant merely because none of its endpoints appears in the current list entry. Conversely, if only its extended line passes through $P$ while its segment range does not cover it, it is not a participant. Chapter 3's [point-membership check](./exact-predicates.mdx#第二节含有点输入时检查这个点属于哪里) must still pass.

## Section 3: When many segments meet, the scheduled pair is not everyone {/* #第三节多线共点预约的一对不是全体 */}

Now take $A,B,C$ and add $\teachEmerald{D}$. Observe only their event at $P$, without replaying the entire sweep. $D$ runs from $(2,0)$ to $(7,10)$ on $y=2x-4$, with range $2\le x\le7$. At $x=4$, $2\times4-4=8-4=4$, and $2<4<7$, so $D$ also passes strictly through $P$.

All four inputs are now fixed; later examples retain these letters, coordinates, and meanings. Their other endpoints have horizontal coordinates $0,1,2,7,8,9$, distinct from $P$'s coordinate $4$ and from each other.

For example, checking old neighbors $A,C$ may already have discovered $P$. That discovery establishes a future stop at $P$, but does not imply that only $A,C$ should be processed on arrival. $B$'s start, $A$'s end, and the passages of $C,D$ all belong to the same event.

### Register the position once and merge endpoint information {/* #位置只登记一次端点信息要合并 */}

Reuse Chapter 3's result that [both coordinates must respectively agree for points to be identical](./exact-predicates.mdx#第七节事件先后与同点识别分别比较什么). If another input pair later computes $P$ too, use the same existing position in the list. Merge information about which inputs start and end there, rather than overwriting existing information.

Every input endpoint is known beforehand, so the list can retain the starters and enders at each position; point-input handling is added shortly. Even when a neighboring pair alone discovers an intersection, registration need only ensure that the real position stays on the list. **Collect every participant anew on arrival; the pair that scheduled the event is not the full participant set.**

Continue to use Chapter 2's rule of [retaining real future intersections until removal from the list](./why-neighbors.mdx#一份待处理清单). Temporarily losing adjacency does not cancel a confirmed event position. The list returns the leftmost unprocessed position; each position is removed and handled together only once.

### Use roles to distinguish current pairing from later membership {/* #用角色区分当前配对与后续成员 */}

First assign roles to the current event's nonzero participants. Continue to write its position as $P=(x_P,y_P)$, where $x_P,y_P$ are its horizontal and vertical coordinates, both $4$ in this example. The rules below do not depend on that value. Identify the left and right endpoints of each nonzero segment by horizontal coordinate, independently of the original written endpoint order. If it contains $P$, it has exactly one of these roles:

| Role | Exact condition | Active to the right of $P$? |
| --- | --- | --- |
| Starting member | Left endpoint is $P$; right endpoint has horizontal coordinate greater than $x_P$ | Yes |
| Ending member | Right endpoint is $P$; left endpoint has horizontal coordinate less than $x_P$ | No |
| Strictly through member | $P$ belongs to the segment, with horizontal coordinate strictly between its endpoints | Yes |

Being nonzero and nonvertical guarantees distinct left and right endpoints, so these three roles do not conflict. In the four-input example, $B$ starts, $A$ ends, and $C,D$ pass strictly through. All participate in current pairing, but only $B,C,D$ remain on the right.

### How to collect every old active participant {/* #怎样找齐旧活动参与者 */}

Call the active order immediately left of $P$ the “old order.” Its segments through $P$ include ending and strictly through members; starters have not entered yet. Call the consecutive portion consisting of these old participants the “meeting block.” With no old participants, it is empty.

Why must they be consecutive? With fewer than two old participants, the block is empty or has one member. Otherwise choose the lowest and highest participants. Any old member between them still exists on reaching $P$: it cannot end in the immediately preceding event-free interval, and even if it ends exactly at $P$, its closed segment includes that endpoint.

Now use Chapter 2's [height-difference argument for a segment between two others](./why-neighbors-proof.mdx#到交点时w-的高度被限制在哪里). At boundary $x_P$, the middle member cannot be below the formerly lower member. Otherwise their positive height difference on the left becomes negative, forcing an intersection in the preceding event-free interval. Nor can it be above the formerly upper member, for the same reason. Both outside participants have height $y_P$ at $P$, so the height between them must also equal $y_P$. The middle member passes through $P$ too.

Chapter 2 excluded this middle member using its prohibition of three segments meeting. We now allow such meetings, and obtain a new conclusion: **the middle member must be included in the meeting block.** We cannot reuse Chapter 2's restriction to keep only the first two selected inputs.

The same boundary argument ensures that evaluating every old member's height at $x_P$ yields a nondecreasing bottom-to-top sequence, possibly with a whole block equal to $y_P$. Otherwise a formerly lower member would become higher here, implying an earlier crossing. We can therefore locate exactly the first old member with height at least $y_P$, then collect consecutive equal-height members until the height differs. If that first member is already higher, there is no equal-height block, only an insertion gap. This can use ordered search, rather than scanning every input each time.

After collecting the whole block, merge inputs starting at $P$ from the list. Ending members should already be in the old block, and the endpoint list also identifies them for checking. Merge by original identifier, keeping each input once. Every nonzero input containing $P$ is either already active on the left or starts here, so these two routes cover all nonzero participants. Old members outside the block have heights different from $y_P$ and do not pass through $P$. New inputs are explicitly supplied by endpoint information, so bystanders are not added without cause.

## Section 4: Why four participants give six results {/* #第四节四份参与者为什么留下六条结果 */}

The four-input example has participants $A,B,C,D$. Use Chapter 1's [method of pairing only with larger original identifiers](./what-we-compute.mdx#怎样把每一对都检查一遍), listing them in original identifier order:

| Current input | Pairs in this row | Complete intersection |
| --- | --- | --- |
| $A$ | $A,B$; $A,C$; $A,D$ | $P=(4,4)$ for every pair |
| $B$ | $B,C$; $B,D$ | $P=(4,4)$ for every pair |
| $C$ | $C,D$ | $P=(4,4)$ |
| $D$ | None | No new result |

There are $3+2+1=6$ results. In this table the letters represent four distinct original identifiers in the listed order; they are not renumbered according to current vertical order.

Why are all six pairs genuine? We established that every participant contains $P$, so any two share at least that point. Chapter 1's [intersection-shape result](./what-we-compute.mdx#为什么不会出现两段分开的公共部分) states that if two closed segments shared another distinct point, they would share a positive-length interval. Such overlap is excluded in this chapter, so the complete intersection is exactly $P$. This holds for any number of participants, not just four.

Pairing only with larger identifiers makes every pair appear once in this event, excludes self-pairing, and prevents reversed order from creating another pair. There is no duplication across events either: under our conditions, any pair's nonempty intersection is one point, and that exact position is processed once. Conversely, for any real point intersection at the current position, both inputs contain that point. Once all participants are collected, that pair must appear. Thus this step neither misses, invents, nor duplicates results.

This also explains precisely what merging positions means: the list retains one $P$, but the results separately retain all six input-pair identities. Six results must not be compressed into a single statement that an intersection exists here.

## Section 5: Zero-length inputs participate here, but do not continue rightward {/* #第五节零长度输入参与这一次不留到右侧 */}

Now take only $C$, together with two new inputs $Z_1,Z_2$, each with both endpoints at $P=(4,4)$. Each consists of one point, but they have distinct original identities.

The two figures show $Z_1,Z_2$ separately so overlapping markers do not obscure one another; they have not been moved to different positions. A diamond does not represent an area, and $C$ is the same input in both figures.

Treating a point input as both a starter and an ender and simply concatenating the lists could insert its identity twice. Instead define a separate “point input” role: an input with coincident endpoints is kept once by original identifier in that position's list, classified separately from nonzero starters and enders.

On reaching $P$, first collect all nonzero participants, then merge point inputs at this position. The participants here are therefore $C,Z_1,Z_2$, giving:

| Original unordered input pair | Complete intersection |
| --- | --- |
| $C,Z_1$ | Point $P$ |
| $C,Z_2$ | Point $P$ |
| $Z_1,Z_2$ | Point $P$ |

Chapter 3 already gave [exact point–segment and point–point decisions](./exact-predicates.mdx#第二节含有点输入时检查这个点属于哪里). What is new here is their place in the sweep: a point input exists only at $x=x_P$ and has no point at any $x>x_P$, so **after pairing it does not enter the active order on the right**. It cannot be placed above or below $C$, and needs no invented supporting line or slope.

Only $C$ exists on both sides in this example. With only $Z_1,Z_2$ and no nonzero segment, their pair must still be reported, while both side orders remain empty. With only $Z_1$, no pair of distinct inputs can be formed, so the result is empty, but the endpoint event is still processed normally.

The same applies when a point lies on a closed endpoint. With only $A,Z_1$, report $P$ for that pair before $A$ ends; the point input does not remain on the right. With only $B,Z_1$, first report their same-point pair, then let $B$ continue alone. Multiple point inputs at one position are paired separately with every nonzero participant and with each other by original identifier. Geometric coincidence does not merge identities.

## Section 6: Report first, then order the entire right-side meeting block {/* #第六节先报告再排出整个右侧相遇块 */}

Return to the event for $A,B,C,D$. Only after all current results have been reported do we update membership: ending member $A$ leaves, strictly through members $C,D$ continue, and starting member $B$ joins. Any point inputs at this position have also completed pairing, but do not participate in later ordering.

We must not perform an arbitrary chain of pairwise swaps based on which input pair scheduled the event first. What needs ordering is the **entire new block** of participants continuing to the right.

### Use the established slope relation to order both sides {/* #用已有的斜率关系排两侧顺序 */}

Reuse Chapter 3's [distinction between equal height at an intersection and order on either side](./exact-predicates.mdx#到了交点等高不等于两侧顺序). For two nonvertical lines through one point with different slopes, the larger slope is above on the right, with the opposite order on the left. This requires only that both segments exist on the side discussed, not that only two segments participate in the event. It can therefore be applied pair by pair to this chapter's meeting block.

Here $m_A,m_B,m_C,m_D$ denote the four supporting lines' slopes. Reading them from $y=4,y=x,y=8-x,y=2x-4$ gives $0,1,-1,2$ respectively. The old members are only $A,C,D$; decreasing slope on the left gives bottom-to-top order $D,A,C$. The new members are only $B,C,D$; increasing slope on the right gives $C,B,D$.

    'Order to the right of P: C, B, D. Only portions active on the right are drawn, leaving the left empty; bottom-to-top slopes are -1, 1, 2.',

The figures show left-side members and order, followed by right-side members and order. Each draws only the portions actually present on that side; retain this reading order if they wrap. The labels $x<4$ and $x>4$ refer to the immediate sides of the event, not sampling at a fixed decimal offset.

Why do pairwise comparisons determine the whole block? Any two new right-side members pass through $P$ and have positive length to the right, so the smaller slope must lie below the larger. Sorting all slopes from small to large simultaneously satisfies every pair's vertical relation. The same reasoning gives the reverse order for old members on the left.

We must also handle equal slopes. Two nonvertical lines through $P$ with the same slope are the same line. If both inputs extend rightward, they share a positive-length interval from $P$ to the earlier right endpoint, violating our conditions. If both arrive from the left, they similarly overlap on the left. Thus two equal-slope members cannot occur in the same side's block, and no arbitrary tie-break is needed.

However, one input ending here and another starting here may have equal slopes. For example, take another input $F$ from $P$ to $(6,4)$, paired only with $A$. Both satisfy $y=4$, with ranges $0\le x\le4$ and $4\le x\le6$. Their only common horizontal coordinate is $x=4$, so their complete intersection is $P$. Only $A$ exists on the left and only $F$ on the right. Pair them first, then replace membership; **do not reorder two simultaneously continuing members**, because these inputs do not continue together. Endpoint-only contact with different slopes also uses role-based insertion and removal, rather than forcing the swap rule for two through members.

### Why order outside the block remains correct {/* #为什么块外顺序仍然正确 */}

Active members outside the old block do not pass through $P$, so their heights at $x_P$ are strictly below or above $y_P$. They have no endpoints at this horizontal coordinate either: that would create a distinct event with the same horizontal coordinate, violating this chapter's assumptions. They therefore exist immediately on both sides.

Take any outside member and any new-block member. If their strict vertical order at $P$ reversed arbitrarily close on the right, Chapter 2's height-difference sign-change result would force an intersection between those positions. That would create an event in the immediate event-free interval on the right, a contradiction. Thus the new meeting block remains between the original outside members below and above. Outside members neither intersect each other nor enter or leave here, so they retain their order.

There are finitely many inputs and no positive-length overlaps, hence finitely many endpoints and point-intersection positions. Distinct event horizontal coordinates ensure an interval free of other events exists on each side. “Immediately” above refers to such an interval for the proof, not to an algorithm guessing a sufficiently small decimal.

If the old block is empty but there are starters, insert the new block in the gap found at $y_P$. If the new block is also empty, retain or connect the two sides of the original gap. This covers start-only, end-only, ordinary-crossing, mixed same-point, and pure-point events.

## Section 7: Which adjacencies need checking after the update {/* #第七节更新以后检查哪些邻接 */}

Write the new block from bottom to top as $K_1,\ldots,K_k$, where $k$ is its member count and $K_i$ its $i$th member. Let $T_-$ denote the outside member immediately below the gap and $T_+$ the one immediately above. These name local positions, not new inputs, and either side may be absent.

When $k\ge1$, this short portion of the updated order is

$$
T_-,\quad K_1,\ldots,K_k,\quad T_+.
$$

Consider only input pairs consecutive in this sequence:

| Position | Adjacency to examine | Action |
| --- | --- | --- |
| Lower boundary | $T_-,K_1$ | If the lower member exists, check real intersection and strict future |
| Inside the new block | $K_1,K_2$ through $K_{k-1},K_k$ | Every pair already intersects at $P$; do not schedule $P$ again as future |
| Upper boundary | $K_k,T_+$ | If the upper member exists, check real intersection and strict future |

For $k=1$ there are no internal adjacencies. Any two block members contain $P$, and overlaps are excluded here, so their intersection is only $P$, with no future intersection possible. We can reject future scheduling directly on that basis. A uniform intersection check would also return only the current position, which the strict-future condition must reject. **After ordering the new block, do not perform an extra swap for some pair that scheduled the event.**

For $k=0$, removing the old block makes $T_-,T_+$ direct neighbors if both exist; check that pair. A missing side means no such new neighboring pair. If the old block was empty too, as in a pure-point event, the sides were already neighbors. There is no new adjacency and a repeated check can be skipped.

Boundary checks continue to use Chapter 3's [real-intersection decision](./exact-predicates.mdx#第五节检查这条路径有没有遗漏) and [strict-future condition](./exact-predicates.mdx#第八节严格未来为何必须排除等号). Empty intersections are not scheduled. A resulting point is future only if its horizontal coordinate is strictly greater than $x_P$. The current position with coordinate $x_P$ has been handled together and is not re-added; positions to its left are not added either. Existing real future positions remain listed and must not be lost because neighbors changed.

Why are these checks sufficient? Outside members are neither inserted, removed, nor reordered relative to each other, so distant old adjacencies remain. Any new adjacency with both inputs in the new block is an internal pair in the table. With only one input in the block, it must cross the upper or lower boundary. With both inputs outside, the only new possibility is connecting the two sides after removing the old block when the new one is empty. Every case is covered. Unchanged adjacencies need not be rechecked every time: they were checked when formed, and their discovered real future positions remain on the list.

The claim that every new adjacency is checked assumes that the previous order was maintained correctly and previous new adjacencies were checked. This section shows how a same-point update preserves that rule; it does not assume that unreached intersections have already been processed.

## Section 8: Why a shared point without an endpoint is also scheduled {/* #第八节没有端点提示的共点为什么也会预约 */}

In the first three examples, $P$ contains an endpoint, so the list knows its position from the start. But if two or more segments all pass strictly through a point, with none starting or ending there, how is it first discovered? Expanding the meeting block on arrival cannot answer this: we still need to explain why arrival happens.

Choose an arbitrary shared point without an endpoint, denoted by $Q=(x_Q,y_Q)$ to distinguish it from the earlier $P$. At least two segments pass strictly through it. Assume only that events to the left of $Q$ have been processed correctly:

1. Real event positions are finite, so an interval without other events can be chosen to the left of $Q$. All inputs through $Q$ pass strictly through it, so they are already active in that interval.
2. Section 3's between-neighbors argument applies at $Q$: any active member between two through members must also pass through $Q$. These through members therefore form a consecutive block of at least two members on the left.
3. Choose any consecutive pair in this block. They are neighbors in the entire active order, not merely after removing bystanders. Look back through the finite earlier events to when this uninterrupted adjacency formed and persisted to the left of $Q$. The initial order was empty, so it must have formed at some time, strictly left of $Q$.
4. By Section 7's classification of all new adjacencies, this pair was checked when it formed. Both inputs contain $Q$, and positive-length overlaps are excluded, so their intersection is exactly $Q$. At that time $Q$ was strictly future. The list therefore either added $Q$ or already contained and retained it.
5. Removing the leftmost unprocessed position by horizontal coordinate eventually exhausts the finite events on the left and reaches the retained $Q$. On arrival, collect the whole block and report all unordered input pairs, not just the pair that scheduled it.

This does not claim that every pair meeting at a point must previously have been adjacent. **At least one earlier neighboring pair suffices to schedule the position; searching on arrival supplies all remaining participants.**

Assuming the left side was correctly processed is not circular. If a first real event position were never reached, it could not be a preregistered endpoint. All events on its left would have arrived and been handled correctly by this chapter's participant, pairing, and order rules. The five steps would then apply, showing that it was scheduled and must arrive, a contradiction. This supplies the discovery argument after allowing many segments at a point. Chapter 2's claim that two chosen crossing segments must be neighbors beforehand depended on excluding triple meetings and cannot be copied unchanged.

## Section 9: Assemble one same-point event into a complete procedure {/* #第九节把一次同点处理接成完整流程 */}

We can now put the established rules together. Each row below is a teaching stage for one event position, not an execution trace of a particular implemented function.

| Stage | Action | Why it belongs here |
| --- | --- | --- |
| Take the position | Remove the leftmost unprocessed position and merge same-point endpoint information | Process one exact position together, once |
| Find participants | Locate the old active meeting block exactly, merge starters and point inputs, and deduplicate by original identifier | Neither the scheduled pair nor the endpoint list alone contains all participants |
| Report | Pair distinct original inputs by smaller and larger identifiers and record complete intersections | Enders still contain the current closed endpoint; each same-point input pair has its own result |
| Update | Remove enders, retain through members, add nonzero starters, and order the new block by right-side slope order | Current participants differ from subsequent active members; point inputs do not continue rightward |
| Check | Check internal and boundary adjacencies of the new block; if empty, check the newly connected outside pair | Cover all new adjacencies and schedule only real positions strictly in the future |

An implementation may temporarily remove a state block from a container to locate or reorder it. Provided it retains every participant and first completes the current intersection reports, this is not premature loss of ending identities. This article specifies which information mathematics depends on and when members cease to qualify as participants; it does not infer an order for internal container operations.

Finally, check the current event against each minimal example. Each row contains only the explicitly listed inputs; do not combine separate examples into one set:

| Example inputs | Old bottom-to-top order | Current participants | Current results | New bottom-to-top order |
| --- | --- | --- | --- | --- |
| $A,B$ | $A$ | $A,B$ | $P$ for $A,B$ | $B$ |
| $B,C$ | $C$ | $B,C$ | $P$ for $B,C$ | $C,B$ |
| $A,B,C,D$ | $D,A,C$ | $A,B,C,D$ | The six pairs listed in Section 4, all at $P$ | $C,B,D$ |
| $C,Z_1,Z_2$ | $C$ | $C,Z_1,Z_2$ | $C,Z_1$; $C,Z_2$; $Z_1,Z_2$, all at $P$ | $C$ |
| $Z_1,Z_2$ | Empty | $Z_1,Z_2$ | $P$ for $Z_1,Z_2$ | Empty |
| $Z_1$ | Empty | $Z_1$ | None | Empty |
| $A,F$ | $A$ | $A,F$ | $P$ for $A,F$ | $F$ |

One position is processed once but can yield many retained results. Ending members participate in closed-endpoint pairing before leaving; point inputs retain their own identities; and the right-side order keeps only nonzero members that genuinely continue. Distinguishing these three facts lets starts, ends, and crossings be handled together in one event.

This chapter separately established participant completeness, genuine results reported once, correct post-event order, sufficient new-neighbor checks, and discovery even without endpoint hints. The arguments require no positive-length overlap, nonvertical nonzero inputs, and distinct horizontal coordinates for distinct events. Chapter 6 handles distinct positions with equal horizontal coordinates, and Chapter 7 introduces shearing. The complete mixed-input sweep, general correctness, and total work are left to Chapters 8–10 respectively.

The previous chapter, [What Are We Trying to Compute?](./what-we-compute.mdx), established pairwise checking as a baseline. Checking every input pair for a common part misses no result, but many of those segments are far apart.

This time, we move a vertical auxiliary line from left to right and stop only where necessary. This is called a “sweep line.” Our question is: **if we check only segments that are immediately next to each other vertically, might we miss a pair that starts far apart and intersects later?**

Chapter 2 has two parts. Here we follow an example to see how neighbors change during the sweep and how future intersections are discovered. [Part 2: Why No Intersection Is Missed](./why-neighbors-proof.mdx) then extends the reasoning to every input allowed in this chapter. After this part, you can pause and try to explain the three event rules in your own words.

## State the Assumptions First {/* #先把本章的条件说清楚 */}

To see the basic mechanism clearly, we temporarily require the following:

- Every segment has positive length and is nonvertical.
- No two segments overlap, no endpoint lies on another segment, and no point lies on three or more segments.
- All endpoints and intersections have different horizontal coordinates.

Thus, each intersection lies in the interiors of exactly two segments. At each stop, we handle one segment starting, one segment ending, or two segments crossing. Horizontal segments and nonintersecting segments are allowed.

These are teaching assumptions for this chapter, **not reasons for the complete algorithm to reject more complicated inputs**. Later chapters will remove them one by one. Results are still recorded by original unordered input pair; under these assumptions, every nonempty intersection happens to be a point.

## Four Segments, Without Giving Away the Intersections {/* #四条线段先不给交点答案 */}

Use $\teachBlue{A},\teachOrange{B},\teachViolet{C},\teachEmerald{D}$ to distinguish four inputs. All are closed segments and include both endpoints.

| Input | Left endpoint | Right endpoint | Containing line and horizontal range |
| --- | --- | --- | --- |
| $\teachBlue{A}$ | $(0,1)$ | $(10,1)$ | $\teachBlue{y}=\teachBlue{1}$, $0\le x\le10$ |
| $\teachOrange{B}$ | $(1,3)$ | $(3,3)$ | $\teachOrange{y}=\teachOrange{3}$, $1\le x\le3$ |
| $\teachViolet{C}$ | $(2,6)$ | $(9,-1)$ | $\teachViolet{y}=\teachViolet{8-x}$, $2\le x\le9$ |
| $\teachEmerald{D}$ | $(4,0)$ | $(8,4)$ | $\teachEmerald{y}=\teachEmerald{x-4}$, $4\le x\le8$ |

You can check the equations using the endpoints. For $C$, when $x=2$, $y=8-2=6$; when $x=9$, $y=8-9=-1$. For $D$, when $x=4$, $y=4-4=0$; when $x=8$, $y=8-4=4$. Two endpoints determine the containing line, and the bounds restrict it to the segment. To review the distinction, see [Writing a Line Equation from Two Endpoints](./line-equation.mdx).

## What Do We Keep Track of During the Sweep? {/* #扫描时记住什么 */}

When a segment starts, ends, or crosses another, the segments met by the sweep line or their vertical relationship can change. A position where we must stop and process such a change is called a “sweep event.” The two records below answer “who is next to whom now?” and “where do we go next?”

### An Order from Bottom to Top {/* #一份从下到上的顺序 */}

The sweep line's position is given by its horizontal coordinate $x$. Away from endpoints and intersections, input segments meeting the sweep line are called the current “active segments.” Since no input is vertical, each active segment meets the sweep line at one point. We can arrange the segments from bottom to top by those points' heights. This list is called the “active order.”

“Neighbors” means two immediately consecutive segments in this list, with no active segment between them. For example, in the order $A,B,C$, the neighbors are $A$ and $B$, and $B$ and $C$; $A$ and $C$ are not neighbors yet.

At an event, distinguish before processing from after processing. Before processing, use the order immediately to the left; afterward, use the order immediately to the right. “Immediately” means without crossing another event, not moving an arbitrary fixed distance. At an intersection the two heights are equal, but the orders on its left and right are each well defined.

### A List of Pending Events {/* #一份待处理清单 */}

All endpoints are known from the start, so place them in a “pending list,” sorted by increasing horizontal coordinate. Each time, take the leftmost position from this list. Future intersections newly discovered during processing are also inserted in horizontal-coordinate order.

The initial list for our example is:

| Horizontal coordinate | Known event |
| --- | --- |
| $0$ | $A$ starts |
| $1$ | $B$ starts |
| $2$ | $C$ starts |
| $3$ | $B$ ends |
| $4$ | $D$ starts |
| $8$ | $D$ ends |
| $9$ | $C$ ends |
| $10$ | $A$ ends |

**This list does not contain any crossing events yet.** “Discovering” means checking a segment pair and computing and confirming its intersection. “Registering” means placing an intersection we have not reached into the list for later processing. “Reporting” happens when the sweep line actually reaches the intersection: only then do we record this input pair's result and handle its order change. These are not all the same moment.

Register a given crossing only once. In this chapter, we retain every real future intersection already discovered: even if its two segments temporarily stop being neighbors, we do not remove it. If another check finds the same intersection, we do not insert a duplicate. This keeps the explanation focused on when intersections are discovered, without introducing a procedure for canceling scheduled events.

## Learn About Neighbors from Start Events {/* #从开始事件认识邻居 */}

At $x=0$, $A$ starts. The active order consists only of $A$, with no neighbor to check.

At $x=1$, $B$ starts. The height of $A$ is $1$ and that of $B$ is $3$, giving order $A,B$. Check the pair: one requires $y=1$ and the other $y=3$, which cannot both hold. They have no intersection.

At $x=2$, $C$ starts. Its height is $8-2=6$, above $B$ at $3$, so the order becomes $A,B,C$.

  panels={['After processing C starting at x=2, the bottom-to-top active order is A, B, C. D has not started and is shown faintly. No intersections have been discovered.']}
/>

The vertical dashed line marks the current event position. The bottom of the figure lists the **bottom-to-top order after processing**. Segments that have not started or have already ended are faint; their positions remain visible to help compare successive states.

The new neighbors are $B$ and $C$. A common point's vertical coordinate must satisfy both $y=3$ and $y=8-x$, so

$$
3=8-x.
$$

Add $x$ to both sides to obtain $3+x=8$, then subtract $3$ from both sides to obtain $x=5$. Substituting into $y=3$, the two **lines** intersect at $(5,3)$.

However, $B$ ends at $x=3$. Since $5>3$, this point is not on $B$, so no future crossing is added to the list. We still do not check $A$ against $C$, because $B$ is between them.

**Start-event rule: insert the new segment in the correct position and check it against its neighbors above and below.** If one side has no neighbor, skip that side.

Why are these the only new checks needed? No other endpoint or intersection is at this start event, so the relative heights of the existing segments do not change. Inserting one segment can only split one old neighboring pair and create adjacencies on the new segment's two sides. Every other adjacency stays exactly as it was.

## An Intervening Segment Ends, Revealing a Distant Intersection {/* #中间线段结束远处的交点才被发现 */}

At $x=3$, $B$ ends. Removing it changes the order from $A,B,C$ to $A,C$.

Now $A$ and $C$ are neighbors. The height of a common point satisfies

$$
\teachBlue{1}=\teachViolet{8-x}.
$$

Add $x$ to both sides to obtain $1+x=8$, then subtract $1$ to obtain $x=7$. Substitute into $y=1$: the intersection is $(7,1)$, which we call $P$.

Check the bounds: $7$ is within $A$'s range from $0$ to $10$ and $C$'s range from $2$ to $9$. It is indeed an intersection of the segments. Since $7>3$, it lies to the right of the current sweep position, so add $P$ to the list.

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="end"
  panels={['After processing B ending at x=3, A and C are neighbors and the future intersection P=(7,1) is discovered. P is marked by a hollow circle and has not been reported.']}
/>

A hollow circle marks an intersection already discovered but not yet reached. The remaining horizontal coordinates in the list are $4,7,8,9,10$. **Discovering $P$ does not mean jumping straight to it: we must process the endpoint at $x=4$ first.**

**End-event rule: remove the ending segment. If it had both a neighbor below and a neighbor above, check those two new neighbors.** If there is a neighbor on only one side, removing the segment creates no new neighboring pair.

Again, the reason is a local change: no other segment crosses, starts, or ends here, so the others retain their relative order. Only the two segments formerly separated by the removed one can become adjacent.

## A Newly Starting Segment Adds an Earlier Intersection {/* #新加入的线段让清单多了一个更早的交点 */}

At $x=4$, $D$ starts at $(4,0)$. Here $A$ has height $1$ and $C$ has height $8-4=4$, so the order after processing is $D,A,C$.

The only new adjacency is $D$ with $A$; there is no segment below $D$. Set their heights equal:

$$
\teachEmerald{x-4}=\teachBlue{1}.
$$

Add $4$ to both sides to obtain $x=5$. Substitute into $y=1$: the intersection is $(5,1)$, which we call $Q$. The value $5$ is within both $A$'s range from $0$ to $10$ and $D$'s range from $4$ to $8$. Also, $5>4$, so we can add it to the list.

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="insert"
  panels={['After processing D starting at x=4, the order is D, A, C. Q=(5,1) is discovered and precedes the previously discovered P in the list. Neither intersection has been reported.']}
/>

The remaining positions are now $5,7,8,9,10$. Although $P$ was discovered earlier, $Q$ must be processed first because $5<7$. The list is sorted by position, not discovery time.

## After a Crossing, New Neighbors Reveal a Third Intersection {/* #交叉以后新的邻居带来第三个交点 */}

### At Q, A and D Exchange Order {/* #在-q-处a-与-d-交换顺序 */}

At $x=5$, the sweep line reaches $Q$. Report “input pair $A$ and $D$, with intersection point $(5,1)$.”

Why does their order change? The height of $A$ is always $1$. For $D$, when $x<5$, $x-4<1$, so it is below $A$; when $x>5$, $x-4>1$, so it is above $A$. Thus the order before processing, $D,A,C$, becomes $A,D,C$ afterward.

$A$ and $D$ are still neighbors, but their vertical order is reversed. The new adjacency is $D$ with $C$. Check this pair:

$$
\teachEmerald{x-4}=\teachViolet{8-x}.
$$

Add $x$ to both sides to obtain $2x-4=8$. Add $4$ to both sides to obtain $2x=12$. Divide both sides by the nonzero number $2$ to obtain

$$
x=6.
$$

Substitute into $y=x-4$:

$$
y=6-4=2.
$$

Call this intersection $R=(6,2)$. Its horizontal coordinate $6$ is within $C$'s range from $2$ to $9$ and $D$'s range from $4$ to $8$. Since $6>5$, it lies to the right of the current position, so add it to the list.

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="cross"
  panels={['After processing the crossing at Q with x=5, the order is A, D, C. Q has been reported and is a filled circle. New neighbors D and C reveal the future intersection R=(6,2). P and R remain hollow circles.']}
/>

A filled intersection point has already been reported. The remaining positions in the list are now $6,7,8,9,10$. $A$ and $C$ are temporarily not neighbors, but their registered real intersection $P$ remains in the list.

**Crossing-event rule: exchange the two crossing segments' vertical positions and check the newly created outer adjacencies.** For example, if the order is $L,U,V,H$ and $U,V$ cross, it becomes $L,V,U,H$. Check $L,V$ and $U,H$, skipping any outer neighbor that does not exist. These letters simply represent four consecutive segments.

Why not check more distant segments? No third segment passes through this intersection under our assumptions, so the local change involves only these two segments; outside segments keep their relative order. The crossing segments remain each other's neighbors. They have just intersected, and two distinct lines cannot have a second intersection, so we do not need to look for another crossing of this same pair either. The next part will prove that the segments must indeed be neighbors immediately before crossing.

### At R, C and D Exchange Order {/* #在-r-处c-与-d-交换顺序 */}

At $x=6$, report “input pair $C$ and $D$, with intersection point $(6,2)$.”

The height of $D$ minus the height of $C$ is

$$
(x-4)-(8-x)=x-4-8+x=2x-12.
$$

When $x<6$, multiply both sides by positive $2$ to get $2x<12$, so $2x-12<0$ and $D$ is below $C$. When $x>6$, the same operation gives $2x>12$, so $2x-12>0$ and $D$ is above $C$. The order therefore changes from $A,D,C$ to $A,C,D$.

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="next"
  panels={['After processing the crossing at R with x=6, the order is A, C, D. Q and R have been reported. A and C become neighbors again and give P, but P is already in the list and is not registered twice.']}
/>

The new adjacency is $A$ with $C$. The check again gives $P=(7,1)$, but it is already in the list, so we do not add a second copy. The remaining positions are $7,8,9,10$.

### At P, A and C Exchange Order {/* #在-p-处a-与-c-交换顺序 */}

At $x=7$, report “input pair $A$ and $C$, with intersection point $(7,1)$.” Their height difference, $C$ minus $A$, is $(8-x)-1=7-x$: positive to the left of $7$, negative to its right. Thus the order changes from $A,C,D$ to $C,A,D$.

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="last"
  panels={['After processing the crossing at P with x=7, the order is C, A, D. All three intersections have been reported. The new neighbors A and D intersect at Q, to the left of the sweep line, so Q is not added to the list.']}
/>

The new adjacency is $A$ with $D$. Their intersection $Q$ is at $x=5$, already to the left of the sweep line. It is not a future event, so it is not added to the list again.

Next process $D$ ending at $x=8$, $C$ ending at $x=9$, and $A$ ending at $x=10$, in that order. In none of these cases does the ending segment have old neighbors on both sides, so no new neighboring pair is created. Finally, both the active order and the pending list are empty, and the sweep ends.

## Put Every Event into One Record Table {/* #把每个事件放回同一张记录表 */}

The order in this table is always from bottom to top, after processing. A “new check” means a pair checked now because an adjacency changed. The pair may have been checked before; this does not necessarily mean its first check.

| Current event | Order afterward | Neighbors checked now | Intersection newly added to list | Reported now |
| --- | --- | --- | --- | --- |
| $x=0$, $A$ starts | $A$ | None | None | None |
| $x=1$, $B$ starts | $A,B$ | $A,B$: no intersection | None | None |
| $x=2$, $C$ starts | $A,B,C$ | $B,C$: line intersection beyond $B$ | None | None |
| $x=3$, $B$ ends | $A,C$ | $A,C$ | $P=(7,1)$ | None |
| $x=4$, $D$ starts | $D,A,C$ | $D,A$ | $Q=(5,1)$ | None |
| $x=5$, reaching $Q$ | $A,D,C$ | $D,C$ | $R=(6,2)$ | $A,D$ at $Q$ |
| $x=6$, reaching $R$ | $A,C,D$ | $A,C$: $P$ already listed | None | $C,D$ at $R$ |
| $x=7$, reaching $P$ | $C,A,D$ | $A,D$: $Q$ already to the left | None | $A,C$ at $P$ |
| $x=8$, $D$ ends | $C,A$ | None | None | None |
| $x=9$, $C$ ends | $A$ | None | None | None |
| $x=10$, $A$ ends | Empty | None | None | None |

The table shows two sources of new neighbors that are easy to overlook: at $x=3$, the intervening $B$ ends, bringing together $A,C$; at $x=5$, $A,D$ cross, bringing together $D,C$. Neither pair was adjacent at the start.

## Pause and Connect the Three Rules {/* #先停下来把三类规则连起来 */}

Throughout the sweep, we maintain the bottom-to-top active order and the pending list sorted by horizontal coordinate.

- A segment starts: insert it in the correct position and check its neighbors above and below.
- A segment ends: remove it and check the two segments it used to separate.
- Two segments cross: report this input pair's result, exchange their order, and check the new outer adjacencies.

Every check must confirm that the intersection belongs to both segments and lies strictly to the right of the current sweep position. Only then is it registered. Keep just one copy of each real future intersection, even if its segments temporarily stop being neighbors, and report it when reached.

Now cover the table and try answering: why was $P$ discovered before $Q$ but reported after it? Why do removing $B$ and exchanging $A,D$ both create new neighbors? If you can explain these two points, you have understood this part's sweep process.

Following one example does not yet prove that no allowed input can be missed. The remaining question is whether a pair that begins far apart must become neighbors before crossing, early enough to be checked.

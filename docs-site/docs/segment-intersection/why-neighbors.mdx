上一章[《我们究竟要求什么》](./what-we-compute.mdx)用两两检查建立了基准方法。每对输入是否有公共部分，都检查一次，结果不会漏掉；可是，其中许多线段相隔很远。

这一次，我们让一条竖直辅助线从左向右移动，只在必要的位置停下来。这条辅助线叫作「扫描线」。我们要回答：**如果每次只检查上下紧挨着的线段，会不会漏掉原本隔得很远、后来才相交的一对？**

第二章分成上下两篇。本篇先跟随一个案例，看邻居怎样随扫描过程更新、未来交点怎样被发现；下篇[《为什么不会漏掉交点》](./why-neighbors-proof.mdx)再把理由推广到本章允许的所有输入。读完本篇，可以先停下来，尝试独立复述三类事件的规则。

## 先把本章的条件说清楚

为了先看清基础机制，本章暂时要求：

- 每条线段长度大于零，且不竖直。
- 没有两条线段重叠，没有端点落在另一条线段上，也没有三条或更多线段经过同一个点。
- 所有端点和交点的横坐标互不相同。

因此，每个交点都在恰好两条线段的内部；每次停下，只处理一条线段的开始、结束，或者两条线段的交叉。水平线段、互不相交的线段都可以出现。

这些是本章的教学条件，**不是完整算法拒绝复杂输入的理由**。后续章节会逐步解除它们。本章的求交结果仍按原始无序输入对记录，只是在这些条件下，每个非空交集都是一个点。

## 四条线段，先不给交点答案

用 $\teachBlue{A},\teachOrange{B},\teachViolet{C},\teachEmerald{D}$ 区分四份输入。它们都是闭线段，包含两端。

| 输入 | 左端点 | 右端点 | 所在直线及横坐标范围 |
| --- | --- | --- | --- |
| $\teachBlue{A}$ | $(0,1)$ | $(10,1)$ | $\teachBlue{y}=\teachBlue{1}$，$0\le x\le10$ |
| $\teachOrange{B}$ | $(1,3)$ | $(3,3)$ | $\teachOrange{y}=\teachOrange{3}$，$1\le x\le3$ |
| $\teachViolet{C}$ | $(2,6)$ | $(9,-1)$ | $\teachViolet{y}=\teachViolet{8-x}$，$2\le x\le9$ |
| $\teachEmerald{D}$ | $(4,0)$ | $(8,4)$ | $\teachEmerald{y}=\teachEmerald{x-4}$，$4\le x\le8$ |

表中的方程可以用端点核对。例如，$C$ 在 $x=2$ 时有 $y=8-2=6$，在 $x=9$ 时有 $y=8-9=-1$；$D$ 在 $x=4$ 时有 $y=4-4=0$，在 $x=8$ 时有 $y=8-4=4$。两端点确定所在直线，范围再把它限制为线段。需要回顾这个区别，可以读[由两个端点写出直线方程](./line-equation.mdx)。

## 扫描时记住什么

线段开始、结束或者交叉，会改变扫描线遇到的线段或它们的上下关系。我们把这样需要停下来处理的位置叫作「扫描事件」。下面的两份记录分别回答「当前谁挨着谁」和「接下来去哪里」。

### 一份从下到上的顺序

扫描线的位置用横坐标 $x$ 表示。不在端点或交点上时，与扫描线相交的输入线段叫作当前的「活动线段」。因为输入不竖直，每条活动线段只与扫描线相交于一点，可以按这些点的高低，从下到上排成一列。这一列叫作「活动顺序」。

这里的「邻居」就是这列中直接相邻的两条线段，中间没有另一条活动线段。例如，顺序为 $A,B,C$ 时，邻居是 $A$ 与 $B$、$B$ 与 $C$；$A$ 与 $C$ 还不是邻居。

到了一个事件位置，我们区分处理前、处理后：处理前取扫描线紧靠该位置左侧的顺序，处理后取紧靠右侧的顺序。「紧靠」表示尚未越过下一个事件，不是任意跳一段固定距离。交点处两条线段的高度相等，但左右两侧的顺序各自明确。

### 一份待处理清单

所有端点一开始就已知，所以先把它们按横坐标从小到大放入「待处理清单」。每次取出清单中最靠左的位置；处理时新发现的未来交点，也按横坐标加入清单。

本例开始时的清单是：

| 横坐标 | 已知事件 |
| --- | --- |
| $0$ | $A$ 开始 |
| $1$ | $B$ 开始 |
| $2$ | $C$ 开始 |
| $3$ | $B$ 结束 |
| $4$ | $D$ 开始 |
| $8$ | $D$ 结束 |
| $9$ | $C$ 结束 |
| $10$ | $A$ 结束 |

**这份清单目前没有交叉事件。**「发现」是检查一对线段，算出并确认它们有交点；「登记」是把尚未到达的交点放入清单，留待之后处理；「报告」则发生在扫描线真正到达交点时，此时才记下该输入对的求交结果并处理换序。三者并不是同一时刻发生的事。

清单中同一个交叉只登记一次。本章保留已经发现的真实未来交点：即使那两条线段后来暂时不相邻，也不删除它；再次检查到同一个交点时不重复加入。这样讲解的重点是何时发现交点，不需要引入取消预约的管理办法。

## 从开始事件认识邻居

扫描到 $x=0$，$A$ 开始，活动顺序只有 $A$，没有邻居需要检查。

到 $x=1$，$B$ 开始。$A$ 的高度是 $1$，$B$ 的高度是 $3$，所以顺序变成 $A,B$。检查这一对：一个要求 $y=1$，另一个要求 $y=3$，无法同时成立，没有交点。

到 $x=2$，$C$ 开始。它的高度是 $8-2=6$，高于 $B$ 的 $3$，顺序变成 $A,B,C$。

  panels={['处理 x=2 的 C 开始事件后，活动顺序从下到上为 A、B、C。D 尚未开始，淡色显示。没有已发现的交点。']}
/>

竖直虚线表示当前事件位置，图底部列出**处理后从下到上**的顺序。尚未开始或已经结束的线段淡色显示；仍保留它们的位置，方便前后对照。

这次新出现的邻居是 $B$ 与 $C$。求公共点时，纵坐标必须同时满足 $y=3$ 和 $y=8-x$，因此：

$$
3=8-x.
$$

两边加上 $x$，得到 $3+x=8$；两边减去 $3$，得到 $x=5$。代回 $y=3$，两条**直线**相交于 $(5,3)$。

可是，$B$ 到 $x=3$ 就结束了，$5>3$，这个点不在 $B$ 上。因此没有未来交叉加入清单。此时仍不检查 $A$ 与 $C$，因为中间隔着 $B$。

**开始事件的规则：把新线段放进正确位置，只检查它与上下邻居。** 如果一侧没有邻居，那一侧就不检查。

为什么只需要这些新检查？在一个开始事件处，没有其他端点或交点，原来各条线段的相对高低没有改变。插入一条新线段，只可能拆开原来的一对邻居，并产生新线段两侧的邻接；其他邻接与刚才完全一样。

## 中间线段结束，远处的交点才被发现

到 $x=3$，$B$ 结束。移去 $B$ 后，顺序从 $A,B,C$ 变成 $A,C$。

现在 $A$ 与 $C$ 成了邻居。公共点的高度满足：

$$
\teachBlue{1}=\teachViolet{8-x}.
$$

两边加上 $x$，得到 $1+x=8$；再减去 $1$，得到 $x=7$。代入 $y=1$，交点是 $(7,1)$，记作 $P$。

检查范围：$7$ 在 $A$ 的 $0$ 到 $10$ 之间，也在 $C$ 的 $2$ 到 $9$ 之间，确实是两条线段的交点。又因为 $7>3$，它在当前扫描位置的右边，所以把 $P$ 加入清单。

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="end"
  panels={['处理 x=3 的 B 结束事件后，A 与 C 相邻，发现未来交点 P=(7,1)。P 用空心圆标记，尚未报告。']}
/>

空心圆表示已经发现、尚未到达的交点。此时清单余下的横坐标依次为 $4,7,8,9,10$。**发现了 $P$，不等于立刻跳到 $P$：还要先处理 $x=4$ 的端点。**

**结束事件的规则：移去结束的线段，如果它原来上下两侧都有邻居，就检查这两个新邻居。** 如果只剩一侧，移去它没有产生新的邻接对。

理由也来自局部变化：其他线段没有在这里交叉或开始结束，相对顺序不变；只有被移走线段原来隔开的两条线段可能接到一起。

## 新加入的线段，让清单多了一个更早的交点

到 $x=4$，$D$ 从 $(4,0)$ 开始。此处 $A$ 的高度是 $1$，$C$ 的高度是 $8-4=4$，所以处理后的顺序是 $D,A,C$。

新邻接只有 $D$ 与 $A$；$D$ 下方没有线段。令两个高度相等：

$$
\teachEmerald{x-4}=\teachBlue{1}.
$$

两边加上 $4$，得到 $x=5$；代入 $y=1$，交点是 $(5,1)$，记作 $Q$。$5$ 同时在 $A$ 的 $0$ 到 $10$、$D$ 的 $4$ 到 $8$ 之间，而且 $5>4$，可以加入清单。

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="insert"
  panels={['处理 x=4 的 D 开始事件后，顺序为 D、A、C。发现 Q=(5,1)，清单中 Q 在先前发现的 P 前面。两个交点均尚未报告。']}
/>

清单余下的位置现在是 $5,7,8,9,10$。$P$ 虽然发现得早，$Q$ 却必须先处理，因为 $5<7$。清单按位置排序，不按发现时间排序。

## 交叉以后，新的邻居带来第三个交点

### 在 Q 处，A 与 D 交换顺序

到 $x=5$，扫描线到达 $Q$，报告「输入对 $A$ 与 $D$，交集为点 $(5,1)$」。

为什么发生换序？$A$ 的高度恒为 $1$。对 $D$，当 $x<5$ 时，$x-4<1$，它在 $A$ 下方；当 $x>5$ 时，$x-4>1$，它在 $A$ 上方。因此，处理前的 $D,A,C$ 变成处理后的 $A,D,C$。

$A$ 与 $D$ 仍然相邻，只是上下颠倒；新出现的邻接是 $D$ 与 $C$。检查这一对：

$$
\teachEmerald{x-4}=\teachViolet{8-x}.
$$

两边加上 $x$，得到 $2x-4=8$；两边加上 $4$，得到 $2x=12$；两边除以非零的数 $2$，得到：

$$
x=6.
$$

代入 $y=x-4$，得到：

$$
y=6-4=2.
$$

把这个交点记作 $R=(6,2)$。横坐标 $6$ 在 $C$ 的 $2$ 到 $9$、$D$ 的 $4$ 到 $8$ 之间，又因为 $6>5$，它在当前位置的右边，所以加入清单。

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="cross"
  panels={['处理 x=5 的 Q 交叉事件后，顺序为 A、D、C。Q 已报告，用实心圆表示；新邻居 D 与 C 带来未来交点 R=(6,2)。P 和 R 仍为空心圆。']}
/>

图中实心交点表示已经报告。现在清单余下的位置为 $6,7,8,9,10$。$A$ 与 $C$ 暂时不相邻，但已经登记的真实交点 $P$ 仍保留。

**交叉事件的规则：交换两条交叉线段的上下位置，检查换序后新出现的外侧邻接。** 例如，原顺序为 $L,U,V,H$，其中 $U,V$ 交叉，处理后变成 $L,V,U,H$；需要检查 $L,V$ 和 $U,H$。不存在的外侧邻居跳过。这里的字母只用来表示连续排列的四条线段。

为什么不用检查更远的线段？本章没有第三条线段经过这个交点，交叉附近的变化只涉及这两条线段；外面的线段保持原顺序。两条交叉线段互相仍是邻居，它们刚刚相交，且两条不同直线不可能再有第二个交点，所以也不需要为这一对寻找第二次交叉。下篇会证明：交叉前它们确实必定相邻。

### 在 R 处，C 与 D 交换顺序

到 $x=6$，报告「输入对 $C$ 与 $D$，交集为点 $(6,2)$」。

$D$ 的高度减去 $C$ 的高度，等于：

$$
(x-4)-(8-x)=x-4-8+x=2x-12.
$$

在 $x<6$ 时，两边乘以正数 $2$，得到 $2x<12$，所以 $2x-12<0$，$D$ 在 $C$ 下方；在 $x>6$ 时，同样得到 $2x>12$，所以 $2x-12>0$，$D$ 在 $C$ 上方。因此顺序从 $A,D,C$ 变成 $A,C,D$。

  panels={['处理 x=6 的 R 交叉事件后，顺序为 A、C、D。Q、R 已报告。重新成为邻居的 A、C 对应 P，但 P 已在清单中，不重复登记。']}
/>

新邻接是 $A$ 与 $C$。检查得到的仍是 $P=(7,1)$，但清单里已经有它，不再放入第二份。余下位置为 $7,8,9,10$。

### 在 P 处，A 与 C 交换顺序

到 $x=7$，报告「输入对 $A$ 与 $C$，交集为点 $(7,1)$」。$C$ 与 $A$ 的高度差为 $(8-x)-1=7-x$：在 $7$ 左侧为正，右侧为负，所以顺序从 $A,C,D$ 变成 $C,A,D$。

<IntersectionFigures topic="why-neighbors" prefix="sweep-neighbors" name="last"
  panels={['处理 x=7 的 P 交叉事件后，顺序为 C、A、D。三个交点都已报告。新邻接 A、D 的交点 Q 在扫描线左侧，不加入清单。']}
/>

新邻接是 $A$ 与 $D$。它们的交点 $Q$ 在 $x=5$，已经位于扫描线左侧，不是未来事件，不再加入清单。

接着依次处理 $x=8$ 的 $D$ 结束、$x=9$ 的 $C$ 结束、$x=10$ 的 $A$ 结束。这三次都没有上下两侧同时存在的旧邻居，不产生新的邻接对。最后活动顺序和清单都为空，扫描结束。

## 把每个事件放回同一张记录表

表中的顺序始终从下到上，表示处理后的状态。「新检查」指本次因邻接变化而检查的输入对；它可能以前检查过，不等于第一次检查。

| 当前事件 | 处理后顺序 | 本次新检查的邻居 | 新加入清单的交点 | 本次报告 |
| --- | --- | --- | --- | --- |
| $x=0$，$A$ 开始 | $A$ | 无 | 无 | 无 |
| $x=1$，$B$ 开始 | $A,B$ | $A,B$：不相交 | 无 | 无 |
| $x=2$，$C$ 开始 | $A,B,C$ | $B,C$：延长线交点超出 $B$ | 无 | 无 |
| $x=3$，$B$ 结束 | $A,C$ | $A,C$ | $P=(7,1)$ | 无 |
| $x=4$，$D$ 开始 | $D,A,C$ | $D,A$ | $Q=(5,1)$ | 无 |
| $x=5$，到达 $Q$ | $A,D,C$ | $D,C$ | $R=(6,2)$ | $A,D$ 对应 $Q$ |
| $x=6$，到达 $R$ | $A,C,D$ | $A,C$：$P$ 已在清单中 | 无 | $C,D$ 对应 $R$ |
| $x=7$，到达 $P$ | $C,A,D$ | $A,D$：$Q$ 已在左侧 | 无 | $A,C$ 对应 $P$ |
| $x=8$，$D$ 结束 | $C,A$ | 无 | 无 | 无 |
| $x=9$，$C$ 结束 | $A$ | 无 | 无 | 无 |
| $x=10$，$A$ 结束 | 空 | 无 | 无 | 无 |

这张表呈现两个容易遗漏的来源：在 $x=3$，中间的 $B$ 结束，带来 $A,C$；在 $x=5$，$A,D$ 交叉，带来 $D,C$。它们都不在最初的邻接关系中。

## 先停下来，把三类规则连起来

扫描过程中，我们始终维护从下到上的活动顺序和按横坐标排序的待处理清单。

- 一条线段开始：放到正确位置，检查它与上下邻居。
- 一条线段结束：移去它，检查原来被它隔开的两条线段。
- 两条线段交叉：报告这一输入对的结果，交换顺序，检查新出现的外侧邻接。

每次检查都要确认交点确实属于两条线段，并且严格在当前扫描位置右侧；满足条件才登记。同一个真实未来交点只留一份，即使对应线段暂时不相邻也继续保留，到达时再报告。

现在可以遮住记录表，试着回答：为什么 $P$ 比 $Q$ 先发现，却比 $Q$ 后报告？为什么移去 $B$ 和交换 $A,D$ 都能带来新邻居？能解释这两件事，就抓住了本篇的扫描过程。

不过，跟完一个案例还不能证明任何允许的输入都不会漏。剩下的关键是：原本隔得很远的一对，是否一定在交叉前成为邻居，而且来得及接受检查？下篇[《为什么不会漏掉交点》](./why-neighbors-proof.mdx)从高度差开始，一步步证明这件事。

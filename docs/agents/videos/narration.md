# 配音与字幕制作

适用于仓库 `videos/` 下的视频工程；同时遵循 [视频工程规则](../../../videos/AGENTS.md) 中贯穿各阶段的约束。

音色使用[默认制作配置](configuration.md#默认制作配置)，现有工程的环境与续跑入口见[配音环境与续跑](operations.md#配音环境与续跑)。

## 按教学步骤独立配音

- 页面与配音单元分开管理；同一页面可以包含多个独立的教学步骤和 shot，不得将整页自动视为一个配音单元。
- 在合成前按教学步骤划分口播，每个需要独立播放、停顿的步骤对应一个 shot，并独立合成一条 WAV；一个步骤内可以包含多句连贯口播。划分发生在文本阶段，不得先将多个步骤合成为整页或其他长音频，再裁切成播放片段。
- 每条生成的正式配音必须完整、原速播放。文件裁切、播放器裁切、提前截断及停顿安排统一遵循[完整播放与禁止裁切](timeline.md#完整播放与禁止裁切)，静音处同样不得裁切。

## 无损配音源素材

- 新生成或重新合成的配音必须由 Azure 直接输出 48 kHz、16 bit、单声道 PCM WAV；Speech SDK 使用 `SpeechSynthesisOutputFormat.Riff48Khz16BitMonoPcm`，对应服务格式为 `riff-48khz-16bit-mono-pcm`。原样保存服务返回的 WAV，保持原始语速，不以 MP3、AAC 或其他有损格式作为新配音源素材。
- 合成前核对实际请求的输出格式；合成后检查真实编码为 `pcm_s16le`、采样率为 48000 Hz、位深为 16 bit、声道数为 1，并验证可完整解码。不得仅凭 `.wav` 扩展名声明无损，也不得把已有 MP3／AAC 转为 WAV 后称为无损源音频；转码无法恢复已损失的信息。
- 重试与续跑记录须区分输出格式；不得仅因口播或 SSML 指纹相同就复用旧有损素材作为无损结果。正式采用新 WAV 时，素材引用、实测时间、字幕时间及音频评估须与新音频一致，不沿用旧合成结果的时长或验收结论。
- 本规则用于后续生成，不自动要求重生成已有配音或替换已完成视频。独立试听样本不得自动替换正式素材。历史 MP3 继续可用，但不因封装为 PCM 而宣称恢复无损。成片采用 MOV＋H.265＋PCM，同时保留原始 WAV。
- 时间数据中的 `audioFile` 明确指定当前素材；历史记录缺少此字段时对应原有同名 MP3。新生成的片段写入 WAV 路径；播放器和检查器读取同一字段，不按文件是否存在猜测版本。保留历史文件不会使其覆盖新 WAV。续跑须同时匹配输出格式、口播指纹和音频 SHA-256，并检查实际 PCM 格式。

## 口语稿与读音

### 内容对应与制作顺序

- 按[教学内容呈现](../../../videos/AGENTS.md#教学内容呈现)逐项核对主场景与口头解释。新符号须说明含义和对象对应关系，例如选取 P、Q 后说明 X_P、X_Q 分别表示哪一点的横坐标；不能仅在画面写出定义或用后文读分数代替对象介绍。新增解释按下述制作顺序同步至正式音频、字幕时间和时间线；既有配音仅在仍完整覆盖讲解时复用，未落实时如实记录缺口。
- 制作顺序必须为：先生成并审校字幕文案，再以字幕文案为基础制作独立纯文本口播稿，按[全文审校流程](narration-review.md)完成定稿、拼音标注和迭代审核；在已有音频生成授权时才进入合成，最后依据实测时间数据为既有字幕生成时间戳并检查切换。先生成字幕指先确定供观众阅读的完整文案及自然标点，不要求在配音前猜测时间戳；代表样例和批量制作均遵循此顺序。
- 口播稿从已审校的字幕派生，先在独立副本中完成数学口语化、停顿句号和字母分隔，冻结纯文本后再添加读音标注，不在同一次生成中混做文字定稿与拼音标注。这些合成专用改写不得反向覆盖字幕。禁止先写口播稿再将其直接用作字幕。后续发现内容问题时，先修正字幕文案，再同步核对口播稿与受影响素材。
- 字幕和语音合成输入分开维护，通过稳定的镜头 ID 对应。生成脚本只读取独立口语稿，不以字幕原文兜底；修改字幕后同步核对口语稿。
- 因音频错误进行修复，并更新了最终采用的音频和口播稿时，必须同步受影响片段的字幕，使普通措辞、语序和句式与最终口播一致；同步字幕原稿、分句或语义映射记录及生成字幕，并依据最终音频的实测时间更新字幕时间戳，核对文字对应、切换和受影响排版。字幕保留自然书面标点、数学表达式及原有符号，不得将发音替代词、拼音、IPA 或合成停顿照搬进去，例如口播中的 `queue`、`bee`、`double you` 在字幕中仍写作 `Q`、`B`、`W`。仅改变读音标注或停顿而未改变普通措辞时，字幕文字保持原样，仍核对最终音频对应的时间数据。独立试听样本尚未正式采用时，不据此覆盖正式字幕；同步仅限受影响片段，不全量改写或重生成其他音频。

### 数学表达与读音

- 空格处理必须以对应字幕中的原始含义为依据：先识别中文词组、序数、数值、字母、公式及量词的关系，再决定口播中的分隔。不得仅凭口播字符属于汉字、数字或字母，使用正则或批量替换机械增删空格；数字改写为中文读法后仍须保留其原有数学含义和表达式边界。
- 中文词组内部不加空格。字幕、独立口播稿及拼接后的合成文本均须保持词组连续，例如字幕“第 1 份”表示序数词组，口播写“第一份”，不得写“第 一 份”。不得为避免正常连读、控制读音或模拟停顿而拆开中文词组；读音标注对象的拆分也不得引入空格。英文字母分隔规则不得套用于中文词组；`pinyin` 字段中用于分隔音节的空格不属于朗读文本。
- 数学表达式与中文量词的边界不能按中文词组处理。例如字幕“n-1 种选择”中的 `1` 是 `n-1` 的组成部分，口播“n 减一 种选择”中的“一”仍属于该表达式，不得因“一”和“种”都写成汉字就机械合并为“一种”。反之，字幕“一种选择”本身是中文数量短语，不应拆开。每处处理须能回指对应字幕及其语义；不能从字面确定时，先核对上下文，不猜测改写。
- 读音稿（语音合成输入）禁止使用中文逗号 `，` 和英文逗号 `,`，需要断句时使用句号 `。`。本约束仅针对实际朗读文本，不限制字幕标点或 JSON 等数据格式的语法分隔符。
- 字幕按自然书面语独立使用逗号、句号等标点，保留句内的条件、因果、转折和承接关系；禁止把口播稿为合成停顿而使用的句号照搬到字幕，或将字幕中的逗号统一替换为句号。例如字幕写“为看清两点，这里使用不等比例示意。”，口播可写“为看清两点。这里使用不等比例示意。”。新视频及参考移植同样须独立审校字幕，不能因字幕与口播内容对应而共用标点。
- 字幕切换与时间对齐必须保留字幕原稿的标点；不得为匹配口播短句或时间戳而改写字幕标点。调整字幕标点后，须核对生成字幕是否保留原文，以及短句合并、切换时机和行宽是否合适。
- 数学口语稿应明确区分横纵坐标，用口语表达乘法、负数和下标，并明确分隔列举的字母。
- 朗读带编号的符号或公式时，直接读“字母＋编号”，例如 `a₁` 读“A 一”、`b₂` 读“B 二”，不逐个念成“A 下标一”“B 下标二”。讲解下标概念、说明编号含义或区分符号位置时，可以正常使用“下标”一词，例如“下标一、二表示两条直线的编号”；不得把本规则当作对“下标”一词的全局禁用或机械删除要求。字幕和画面公式保留正常下标写法。
- 单独朗读的英文字母默认统一由合成层使用 `<lang xml:lang="en-US"><say-as interpret-as="characters">…</say-as></lang>` 字母拼读；普通文本中的独立字母与显式字母对象使用同一处理规则。不要求为修复发音将口播稿的小写字母改成大写，默认不使用字母 IPA 或同音单词替换。仅在用户明确确认具体备用方法及目标范围后，才可按[英文字母读音备用方案 skill](../../../.codex/skills/azure-letter-pronunciation/SKILL.md)处理授权目标；禁止主动启用或自动切换方法，本文件的自动修复授权不覆盖该例外。漏读、插入修复允许优先调整字母所在句子的前后文，但须保持语义等价、表达自然且无歧义；除上述已授权例外外保留字母拼读标记。字幕和画面公式保留原有大小写及数学含义。
- 口播稿中相邻且需要逐个朗读的字母须明确分隔，例如画面的 `sY` 在口播稿中写作 `s Y`，或使用分别标注的字母对象；完整英文单词不得拆成字母。合成前检查实际 SSML，确保所有应朗读的字母均使用拼读标记；上述已授权例外须核对目标是否使用用户选定的方法。不能只检查已经被正则匹配到的字母。
- 中文口播中，英文字母尽可能不放在句首或句尾，包括为合成拆出的口播短句。优先通过自然、语义等价的上下文调整，使字母前后有中文承接，例如“C 开始”改为“线段 C 开始”，“最下面是 A”改为“最下面是 A 这条线段”。不得为避开句首、句尾而改变数学含义或机械添加无意义文字；确实不宜改写时保留原表达并整句试听。此规则用于当前授权范围内的制作与修正，不自动触发既有配音的全量改写或重新合成。

### 授权范围与整句试听

- 合成前按本次授权范围核对读音。首次制作或用户明确要求全文处理时检查全文；用户指定某个字、词或句子微调时，只检查目标及判断读音所需的所在整句，不重新审校其他片段，不顺手修改其他词句。后续“修正”“继续”“重新生成”沿用已指定的局部范围，禁止全量重审、重标或重生成。
- 在本次范围内核对多音字选音、声调、语境变调及轻声，按词义、词组和上下文判断，区分数值、序数、数量短语和普通词语，不能机械套用相邻字声调。标错与漏标分别报告；范围外发现只报告，不自动纳入修改或阻止已授权的局部工作。
- 文本检查与实际音频验收分别执行和报告。用户明确只检查文本时，仅审校口语稿及拼音标注，不转为音频检测、试听或合成，不以音频疑点代替文本结论，也不因未试听阻止完成文本检查。检查请求本身不授权修改口播或音频；报告准确说明检查范围及尚未修改的状态。
- 对每一处多音字及需要变调、轻声处理的字，在独立口语稿中使用现有 `text`／`pinyin` 结构作局部读音标注；同字不同语境分别判断，禁止全局替换为同一读音。无法确定的读音先核实，不得猜测后合成。字幕保持正常书写，不以字幕文本替代经过读音处理的口语稿。
- 实际音频的读音验收覆盖本次生成或修改的片段，逐句核对标注及其上下文；局部微调须试听目标所在整句，不能只听孤立字，也不能用文本标注、SSML 校验、音频解码或时间戳代替。获得重新生成授权后，只合成包含目标词句的最小现有独立音频片段，显式指定片段 ID，禁止调用默认全量生成；工具不支持局部生成时报告限制，不扩大生成范围。只更新受影响音频及对应时间数据，复用其他未变素材和有效验收结果。未完成整句试听时明确标记实际音频读音未验收，不得仅改稿件就宣称音频已修复。
- 向用户提供试听样本、配音修正对比或读音验收材料时，必须在同一回复中逐段同时展示完整对照文本和对应的可播放音频，并标明片段 ID 与版本；文本与音频相邻排列，不得只给音频、文件路径、检测结论或要求用户回看先前消息。对照文本须与该版音频的完整口播内容对应，并说明本次读音处理改动，便于逐句核对。
- 列出问题音频供试听、核实或修正对比时，必须在同段音频旁明确指出问题所在：引用具体字词及所在短句，说明应读内容、漏读／插入／错读等问题类型，并区分“自动标记，待试听核实”和“已试听确认”；有可靠时间位置时可一并提供，不猜测时间。不得只给完整对照文本和音频，让用户自行寻找问题。例如指出“‘线段 W 仍然存在’中的 W 漏读”，或“开头‘检查时’中的‘检查’漏读”。修正版本须说明针对哪个原问题、当前是否已核实修复。
- 展示试听对照文本时，遵循[配音检查汇报规则](delivery.md#完工后的全片配音检测)。仅将已核实严重问题涉及的具体字词加粗，其余文本保持普通字重；不得将整句、整段或全部对照文本加粗。为核实而列出的自动标记须按上一条明确定位，但不加粗或宣称已经确认。
- 读音标注只作用于指定片段，不全局替换词语，不改变字幕；拼接普通文本与标注文本后必须保留完整口语稿。

### 输入结构与请求检查

- 采用 `text`／`pinyin` 读音对象时，对象仅含这两个字段；`text` 为无标点的连续汉字，每字对应一个小写拼音音节，单个空格分隔，以 `1`–`5` 标声调（轻声为 `5`，ü 写作 `v`）。标点保留在普通字符串中，字母使用普通字符串或显式字母对象，不混入中文拼音对象；不在口语稿内直接输入 SSML、语速字段或带声调符号的拼音。
- Azure 中文读音标注转换为 `sapi` 音素，例如 `chong2 he2` 转为 `<phoneme alphabet="sapi" ph="chong 2 he 2">重合</phoneme>`；普通文本始终 XML 转义。格式依据 [Azure 中文音素文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-ssml-phonetic-sets#zh-cn)。服务拒绝请求时停止，不丢弃标注后重试。
- 合成前提供不请求服务、不写音频或时长数据的 `--dry-run`，核对本次目标片段的文案、实际音色和 SSML。现有 dry-run 自动读取其他片段不构成重审、修改或重生成其他片段的授权。格式、字段或字数错误须在请求前定位到镜头与片段；格式校验不代表语境读音正确。

## 口播文本的分阶段审校流程

首次全文制作或用户明确要求全文审校时，必须读取并执行[全文审校流程](narration-review.md)，包括独立分工、盲审隔离、历史问题核销及连续两轮通过门禁。指定字词或句子的局部微调按本文件的授权范围与整句核验要求处理，不重启全文流程。

## 字母读音异常的局部短停顿修复

### 漏读与插入优先通过文案修复

- 对漏读（`Omission`）和插入（`Insertion`），先核对独立口播稿、实际 SSML、完整片段音频及识别响应，区分实际音频问题与识别分词或对齐差异，不仅凭自动标记认定错误。确认实际问题后，优先调整措辞、语序或句式，包括字母所在句子的前后文；改写必须语义等价、自然且无歧义，完整保留教学信息、数学含义和应读符号，不通过删去应读内容或把误插内容写入参考稿来消除标记。
- 文案修复须遵循字幕先行、独立口播稿及局部修复范围要求。确有内容问题时先修正字幕，再同步口播；为修复音频而调整普通措辞、语序或句式时，正式采用后按[内容对应与制作顺序](#内容对应与制作顺序)同步字幕，不能以语义等价为由保留旧字幕措辞。数学口语化和发音标注等合成专用表达仍不反向覆盖字幕。保持音色、语速和字母拼读规则不变，只重合成受影响的最小现有独立片段，并以改写后的完整口播稿核验实际音频；文案修改本身不代表音频已修复。
- 不把新增或加长 `break` 作为漏读、插入的默认或首选修复，也不通过堆叠停顿绕过文案调整。仅在已有改写版本的完整音频及识别结果证明问题仍未解决时，才考虑局部 `break` 兜底；保留尝试过的文案、音频及问题证据。下述句界 `400ms/200ms` 规则继续适用，不因本条取消或机械叠加。

### 按原始字幕的语义句界区分停顿

- 后续新生成或重生成口播时，先按语义将原始字幕分成完整句子，再记录每个原句对应的口播分段。原句结束请求 400ms；同一个原句为口播需要拆开的内部边界请求 200ms。口播改写后即使内部短句可以独立成句，也仍按原始字幕所属句子判断，不能将其提升为 400ms。分句记录必须完整、按顺序覆盖原始字幕和独立口播稿，不能仅扫描句号或将所有标点一律视为句界。
- 句号、问号、感叹号及其中英文形式都可能结束句子；省略号、连用标点和引号内的句子按实际语义确定。连用标点在同一句界只产生一次停顿；句末右引号或右括号保留在该句中，不遗漏句界，也不另加停顿。引号、括号、数学小数点、缩写、顿号及保留原样的句内标点本身不产生显式停顿。省略号等歧义位置必须在分句记录中明确其归属，不让程序猜测或静默忽略。
- 保留口播标点，在每个已确认分段结束后放置一个独立的 `{ "breakMs": 400 }` 或 `{ "breakMs": 200 }`，由现有合成层转换为对应的 SSML break。生成前和内容检查复用同一分句校验，检查分句记录与正文一致、停顿缺失、时长错误、位置错误及重复叠加；校验失败不得请求合成。修改正文时重新核对对应分句记录；程序通过不代替语义审校。
- 200ms 是该位置的请求值，不是在 400ms 上追加；二者均不保证实际静音长度，语音服务还可能产生自然停顿。片段末尾同样保留句界请求，页面停留与思考窗口另行编排。以完整口播试听确认清楚且自然；字幕保留自然标点，音色与语速不变，不通过后处理插入静音。本规则不自动要求重生成已有音频，临时试听不得自动替换正式素材。
- 句界连读案例：第⑦集 `242-09` 的“分别交于 H 和 K。H 的横坐标是……”在同一个 WAV 内，原口播输入 `K。H` 没有显式停顿；用户试听反馈句末 K 与下句开头 H 连读。后续生成遵循上述按原始字幕语义句界区分停顿的规则，仍须整句试听确认效果；此记录不代表正式音频已修复。句界停顿与下述问题字母两侧的局部停顿分别判断，不机械叠加。

### 问题字母的局部停顿

- 已有制作或配音修复授权时，句末独立字母漏读采用已确认的自动修复流程，不再逐次要求用户试听或批准相同处理：先核对该片段实际 SSML、完整音频及识别响应，确认漏读后按上文优先调整文案，仅在有改写无效证据时考虑局部停顿，只重合成受影响的最小独立片段。用完整片段的识别与实测词时间确认目标字母已恢复、改写后的全文覆盖完整、没有新增漏读或插入，且格式、解码及时间线校验通过后，自动采用该版并同步口播稿、字幕与时间数据。保留修复前后的文案、音频、SSML 指纹、哈希和原始识别响应；不得通过删除异常标记、猜测时间或放宽检查实现通过。自动流程仍不能确认恢复、出现其他影响可懂性的问题或需改变此处理方案时，才提交具体证据请求用户介入。本条针对句末字母漏读的处理优先于下文逐版试听确认要求，不扩大到正常字母或其他读音问题，也不等同于全片试听或成片验收。
- 独立字母已使用上述英文拼读标记，但整句中仍出现错读、吞音或与邻字粘连时，先核对实际 SSML 和完整音频，不仅凭自动评估标记判断错读。涉及漏读或插入时必须先执行上文的文案修复，不能直接转入短停顿试验。局部停顿仅是候选修复手段，不保证对所有字母、音色和上下文有效，也不全局给正常字母添加停顿。
- 进入局部停顿试验后，保持本轮已确定的完整口播文字、标点、字母拼读标记、音色和语速不变，只在问题字母两侧分别加入独立的 `{ "breakMs": 20 }` 对象，由共享合成层转换为 `<break time="20ms"/>`。可从前后各 20 毫秒开始，必要时对比少量不同停顿版本，选择整句试听确认清楚且自然的最小值；20 毫秒是已成功采用过的起点，不是通用最小值或固定答案。请求值不等于实际静音长度，原标点的自然停顿仍保留；不通过音频后处理插入静音或改变语速。
- 对比样本使用同一完整句子，仅改变局部停顿；按本文件的试听交付要求，同时展示各版完整文本和可播放音频。用户确认前保持样本独立，不替换正式素材；确认后原样复用选中的 WAV，不以相同参数重新合成来代替已确认音频。
- 采用时将局部停顿落实到独立口播输入，核对生成的 SSML 指纹与所选样本一致，并绑定音频 SHA-256。保留旧样本，基于所选音频测量或重新对齐词时间，再生成字幕时间；没有可用合成词边界时使用真实识别结果，不补造时间戳或放宽检查。仍须遵循整批发布门禁，并区分样本确认、接入暂存区和正式发布。

## 数学公式的自然口播

- 朗读公式时按数学含义表达运算层次，使用“……的和”“……的差”“……的乘积”等自然说法，不把括号符号机械读成“括号……括号”。讲解去括号、分配律或括号前负号的作用时，可以明确说“括号”。
- 数学口播须在不看画面公式、不依赖停顿或重音消歧的情况下，明确表达运算对象、整体范围及分组。使用“和、差、乘积”等词不等于已经消除歧义；空格、标点、拼音标注及合成停顿也不能代替语义完整的表达。
- 连续出现多种运算时，检查听者是否能合理地作出另一种运算分组。例如 `n(n-1)` 不得说成“n 乘以 n 与一的差”，因为可能被理解为“n 乘以 n”与一的差，即 `n²-1`；可改为“先求 n 与一的差。再用 n 乘以这个差。”。嵌套表达优先先交代内部运算，再用“所得的差”“这个和”“所得的乘积”等紧邻且明确的指代承接外层运算；乘除、幂、根式及绝对值同样须明确作用范围，不机械套用单一措辞。
- 加减、乘除及分式组合必须说清整体范围与先后顺序。例如 `(X+Y)+(X−Y)` 可说“X 与 Y 的和，加上 X 与 Y 的差”；除以 `b₁b₂` 应说“除以 b₁ 与 b₂ 的乘积”，不能让听众误解成先除以 b₁ 再乘 b₂。
- 复杂公式按运算层次拆句：先交代各项或各个乘积，再说明相加、相减或整体相除；不为一句读完而堆叠“乘、加、减、除”。例如先分别说明两个乘积，再说“用前一个减去后一个”；和与差作为乘数、除数或绝对值的对象时，明确它是一个整体。
- “它们的和”“这个差”等指代只在对象紧邻且明确时使用；“它们的差”还必须已明确被减数与减数的顺序。不能只靠观众看画面猜测指代、运算范围或减法次序。
- 首次全文制作或明确要求全文审校时，审校覆盖本集全部口播，包括已确认的代表样例，检查同类表达；局部修复仍限于[授权范围与整句试听](#授权范围与整句试听)规定的范围，不因本节要求重启全文审核。保留简单、自然且无歧义的读法，不机械把所有公式扩写为长句。按字幕先行、独立口播的流程修正，画面公式保持准确，字幕使用适合阅读的数学符号和自然标点。
- 在授权审校范围内，先仅依据口播文字还原运算分组，再与对应公式核对；若存在另一种合理分组、指代对象不唯一或作用范围不明，须在纯文本阶段改写并复核，不能以“结合画面就能理解”、发音正确或自动评估通过作为放行依据。修正文案后核对当前范围内的同类表达；范围外发现只报告，不自动扩大修改或音频生成范围。
- 修正须落实到受影响的正式音频、字幕时间数据及时间线，只重新合成实际改动片段，保持原速。整句试听应核对自然度、整体范围和运算次序；文本、SSML 或自动对齐检查通过不能代替试听验收。

# 配音与字幕制作

适用于仓库 `videos/` 下的视频工程；同时遵循 [视频工程规则](../../../videos/AGENTS.md) 中贯穿各阶段的约束。

音色使用[默认制作配置](configuration.md#默认制作配置)，现有工程的环境与续跑入口见[配音环境与续跑](operations.md#配音环境与续跑)。

## 无损配音源素材

- 新生成或重新合成的配音必须由 Azure 直接输出 48 kHz、16 bit、单声道 PCM WAV；Speech SDK 使用 `SpeechSynthesisOutputFormat.Riff48Khz16BitMonoPcm`，对应服务格式为 `riff-48khz-16bit-mono-pcm`。原样保存服务返回的 WAV，保持原始语速，不以 MP3、AAC 或其他有损格式作为新配音源素材。
- 合成前核对实际请求的输出格式；合成后检查真实编码为 `pcm_s16le`、采样率为 48000 Hz、位深为 16 bit、声道数为 1，并验证可完整解码。不得仅凭 `.wav` 扩展名声明无损，也不得把已有 MP3／AAC 转为 WAV 后称为无损源音频；转码无法恢复已损失的信息。
- 重试与续跑记录须区分输出格式；不得仅因口播或 SSML 指纹相同就复用旧有损素材作为无损结果。正式采用新 WAV 时，素材引用、实测时间、字幕时间及音频评估须与新音频一致，不沿用旧合成结果的时长或验收结论。
- 本规则用于后续生成，不自动要求重生成已有配音或替换已完成视频。独立试听样本不得自动替换正式素材。历史 MP3 继续可用，但不因封装为 PCM 而宣称恢复无损。成片采用 MOV＋H.265＋PCM，同时保留原始 WAV。
- 时间数据中的 `audioFile` 明确指定当前素材；历史记录缺少此字段时对应原有同名 MP3。新生成的片段写入 WAV 路径；播放器和检查器读取同一字段，不按文件是否存在猜测版本。保留历史文件不会使其覆盖新 WAV。续跑须同时匹配输出格式、口播指纹和音频 SHA-256，并检查实际 PCM 格式。

## 口语稿与读音

- 审校字幕和独立口播稿时，逐项对照主场景首次引入的重要对象、符号、条件、关系及推导，确认有对应口头解释。新符号须说明含义和对象对应关系，例如选取 P、Q 后说明 X_P、X_Q 分别表示哪一点的横坐标；不能仅在画面写出定义或用后文读分数代替对象介绍。
- 画面补充了必要解释时，先同步字幕文案，再更新独立口播稿及实际改动片段的配音、字幕时间和时间线。仅调整画面位置或显示时机不能补足口播内容缺失；已有配音可复用的前提是它仍完整覆盖所需讲解。若修正尚未落实到正式音频，明确记录该缺口，不宣称已经修复。
- 制作顺序必须为：先生成并审校字幕文案，再以字幕文案为基础制作独立纯文本口播稿，按下文“口播文本的分阶段审校流程”完成定稿、拼音标注和迭代审核；在已有音频生成授权时才进入合成，最后依据实测时间数据为既有字幕生成时间戳并检查切换。先生成字幕指先确定供观众阅读的完整文案及自然标点，不要求在配音前猜测时间戳；代表样例和批量制作均遵循此顺序。
- 口播稿从已审校的字幕派生，先在独立副本中完成数学口语化、停顿句号和字母分隔，冻结纯文本后再添加读音标注，不在同一次生成中混做文字定稿与拼音标注。这些合成专用改写不得反向覆盖字幕。禁止先写口播稿再将其直接用作字幕。后续发现内容问题时，先修正字幕文案，再同步核对口播稿与受影响素材。
- 字幕和语音合成输入分开维护，通过稳定的镜头 ID 对应。生成脚本只读取独立口语稿，不以字幕原文兜底；修改字幕后同步核对口语稿。
- 中文与中文之间不加空格。字幕、独立口播稿及拼接后的合成文本均须保持中文词组连续，例如写“第一份”“第二份”“第三份”，不得写“第 一 份”。不得为避免正常连读、控制读音或模拟停顿而在汉字之间插入半角、全角或不换行空格；读音标注对象的拆分也不得引入空格。英文字母分隔规则不得套用于中文；`pinyin` 字段中用于分隔音节的空格不属于朗读文本。
- 读音稿（语音合成输入）禁止使用中文逗号 `，` 和英文逗号 `,`，需要断句时使用句号 `。`。本约束仅针对实际朗读文本，不限制字幕标点或 JSON 等数据格式的语法分隔符。
- 字幕按自然书面语独立使用逗号、句号等标点，保留句内的条件、因果、转折和承接关系；禁止把口播稿为合成停顿而使用的句号照搬到字幕，或将字幕中的逗号统一替换为句号。例如字幕写“为看清两点，这里使用不等比例示意。”，口播可写“为看清两点。这里使用不等比例示意。”。新视频及参考移植同样须独立审校字幕，不能因字幕与口播内容对应而共用标点。
- 字幕切换与时间对齐必须保留字幕原稿的标点；不得为匹配口播短句或时间戳而改写字幕标点。调整字幕标点后，须核对生成字幕是否保留原文，以及短句合并、切换时机和行宽是否合适。
- 数学口语稿应明确区分横纵坐标，用口语表达乘法、负数和下标，并明确分隔列举的字母。
- 朗读带编号的符号或公式时，直接读“字母＋编号”，例如 `a₁` 读“A 一”、`b₂` 读“B 二”，不逐个念成“A 下标一”“B 下标二”。讲解下标概念、说明编号含义或区分符号位置时，可以正常使用“下标”一词，例如“下标一、二表示两条直线的编号”；不得把本规则当作对“下标”一词的全局禁用或机械删除要求。字幕和画面公式保留正常下标写法。
- 单独朗读的英文字母统一由合成层使用 `<lang xml:lang="en-US"><say-as interpret-as="characters">…</say-as></lang>` 字母拼读；普通文本中的独立字母与显式字母对象使用同一处理规则。不要求为修复发音将口播稿的小写字母改成大写，也不再使用字母 IPA、同音单词替换或为字母发音调整前后文的临时方案。字幕和画面公式保留原有大小写及数学含义。
- 口播稿中相邻且需要逐个朗读的字母须明确分隔，例如画面的 `sY` 在口播稿中写作 `s Y`，或使用分别标注的字母对象；完整英文单词不得拆成字母。合成前检查实际 SSML，确保所有应朗读的字母均使用拼读标记，不能只检查已经被正则匹配到的字母。
- 合成前必须逐句、逐字检查完整口语稿中的全部多音字，并逐处按词义、词组和上下文确定读音；不得只处理已被指出的字、数学术语或少数易错字。另须覆盖“一”“不”等变调字及轻声用法，区分数值、序数、数量短语和普通词语，不能机械套用相邻字声调。
- 文本拼音标注检查统一覆盖多音字选音、声调、语境变调及轻声。用户要求检查“多音字”“拼音”或“音调”时，除非明确排除某类，否则不得用语言学分类缩小检查范围。逐句检查完整口语稿及已有标注，同时识别应标未标的位置；标错与漏标分别列出，均纳入汇总。
- 每轮独立全文盲审提交结果后，再核对前次问题清单，保留仍未解决的问题；分类可以辅助解释，不得让问题因改换分类而从总清单消失。问题减少须逐项说明已修复、经证据复核撤回或用户明确排除，不能只报本轮某一类别的数量。每项注明片段 ID、上下文、当前标注、正确读法及判断依据；未核实项单列，不算作通过或确定错误。
- 文本检查与实际音频验收分别执行和报告。用户明确只检查文本时，仅审校口语稿及拼音标注，不转为音频检测、试听或合成，不以音频疑点代替文本结论，也不因未试听阻止完成文本检查。检查请求本身不授权修改口播或音频；报告准确说明检查范围及尚未修改的状态。
- 对每一处多音字及需要变调、轻声处理的字，在独立口语稿中使用现有 `text`／`pinyin` 结构作局部读音标注；同字不同语境分别判断，禁止全局替换为同一读音。无法确定的读音先核实，不得猜测后合成。字幕保持正常书写，不以字幕文本替代经过读音处理的口语稿。
- 实际音频的读音验收必须覆盖全部实际整句音频，逐处核对上述标注及其上下文，确认发音、变调、轻声与断句正确自然；不能用孤立字试听、文本标注、SSML 校验、音频解码或时间戳代替。未完成整句试听时明确标记实际音频读音未验收；发现错读后，在获得修复授权的范围内修正局部口播输入并重新生成受影响音频、更新对应时间数据，再复核整句，不得仅改稿件就宣称音频已修复。
- 向用户提供试听样本、配音修正对比或读音验收材料时，必须在同一回复中逐段同时展示完整对照文本和对应的可播放音频，并标明片段 ID 与版本；文本与音频相邻排列，不得只给音频、文件路径、检测结论或要求用户回看先前消息。对照文本须与该版音频的完整口播内容对应，并说明本次读音处理改动，便于逐句核对。
- 展示试听对照文本时，遵循[配音检查汇报规则](delivery.md#完工后的全片配音检测)，只标出已核实的严重问题，不列出或加粗自动评估疑点。仅将严重问题涉及的具体字词加粗，其余文本保持普通字重；不得将整句、整段或全部对照文本加粗。
- 读音标注只作用于指定片段，不全局替换词语，不改变字幕；拼接普通文本与标注文本后必须保留完整口语稿。
- 采用 `text`／`pinyin` 读音对象时，对象仅含这两个字段；`text` 为无标点的连续汉字，每字对应一个小写拼音音节，单个空格分隔，以 `1`–`5` 标声调（轻声为 `5`，ü 写作 `v`）。标点保留在普通字符串中，字母使用普通字符串或显式字母对象，不混入中文拼音对象；不在口语稿内直接输入 SSML、语速字段或带声调符号的拼音。
- Azure 中文读音标注转换为 `sapi` 音素，例如 `chong2 he2` 转为 `<phoneme alphabet="sapi" ph="chong 2 he 2">重合</phoneme>`；普通文本始终 XML 转义。格式依据 [Azure 中文音素文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-ssml-phonetic-sets#zh-cn)。服务拒绝请求时停止，不丢弃标注后重试。
- 合成前提供不请求服务、不写音频或时长数据的 `--dry-run`，执行完整文案校验并展示实际音色、完整口语稿和 SSML。格式、字段或字数错误须在请求前定位到镜头与片段；格式校验不代表语境读音正确。

## 口播文本的分阶段审校流程

本流程处理文本及拼音，不以生成、试听或检测音频代替。主代理负责交接、版本核对、问题汇总和门禁判断；不得以自己的一次生成及自查替代以下独立工作。执行范围以当前用户授权为准：仅获检查授权时只提交问题，不自动修改；已获制作或修正授权时按阶段自动推进，不逐轮重复索取同一范围的授权。

### 阶段与职责

1. **纯文本定稿**：从已审校字幕派生完整口语稿，保留片段 ID，不加拼音。交给未参与撰写的新子代理审核语义、数学口语表达、对象指代和断句，并逐段检查中文与中文之间没有空格，不得将拆开的中文词组判为通过。问题修正后由独立文本审核子代理复核，通过即自动冻结全文及其版本，不再额外要求用户逐句确认。
2. **首次拼音标注**：另建子代理，只接收冻结全文、适用规则和必要的教学语境。按词义查询本地词典，标注多音字；依据明确规则结合整句处理声调、变调和轻声，同时检查应标未标的位置。查证从首次标注开始，不等审核发现疑点才查。允许调整标注对象的切分，但拼接后的文字、标点、字母及顺序必须与冻结文本完全一致。
3. **独立全文盲审**：每轮新建审核子代理，只接收当前完整稿件、冻结纯文本、适用规则和必要语境。逐句检查全部片段的多音字选音、声调、变调、轻声与漏标，不能抽样或只检查最近改动。先提交带版本和覆盖清单的盲审结果；在此之前不得读取历史问题、上一轮结论、标注者或修正者的查证记录。
4. **历史问题核销**：盲审结果提交后，才向本轮审核子代理提供历史问题清单及已有查证依据。逐项判断已修复、仍存在、需查证或有证据撤回，保留盲审原始结果并追加核销结果，不能覆盖旧报告来制造“无问题”。新增发现与历史未解决项合并为本轮问题清单。
5. **独立拼音修正**：另建修正子代理，只提供当前稿件、冻结纯文本、适用规则和本轮问题清单及其依据。核实问题后只改拼音标注，返回逐项处理结果，不能自行宣布审核通过。若发现文字语义或断句歧义，返回纯文本阶段，由该阶段解决、复核并重新冻结，再重新标注和审核；不得在拼音修正中顺手改词或断句。
6. **重新审核与放行**：修正后回到独立全文盲审。任何文字或拼音修改都使连续无问题轮次归零；只有同一未改动版本连续两轮由不同的新审核子代理完成全文盲审和历史核销，且无新增问题、无历史遗留问题、无待查证项，才允许标记“文本与拼音审校通过”。两轮须顺序执行，后一轮不读取前一轮的结论直到其盲审完成。审核不完整、失败或中断均不计为通过；不能靠达到固定次数强行放行。

### 上下文隔离与查证

- 各阶段的标注、审核、修正和争议查证使用新的子代理；创建时使用不继承历史的方式（如 `fork_turns="none"`），只传该阶段必需材料，不转发整段主对话。不让同一子代理兼任标注、审核和修正；同一轮先盲审后核销是上述明确允许的两步交接。
- 主代理按 `action-authorization` 为每个子代理限定读写范围、允许动作和结束条件。审核及查证只读，修正仅能写明确授权的稿件；不授予音频生成、Git、发布或继续委派能力。共享工作区不会因新建子代理自动隔离，须明确禁止盲审者主动读取旧报告、历史会话和已有查证结论；必要的项目规则仍须提供，不以隔离为由省略。
- 首选 `macos-dictionary` 查询本地词典，保留词典名称、词头、原始标音和释义，区分精确词条、相关词条、无结果与工具失败。该工具只提供词典证据，语境判断由标注或审核阶段另行完成；不得把相关词条的标音直接移用，也不得把词典原调与口播变调不同直接判为错误。
- 变调和轻声须记录适用规则及句内条件，区分数值、序数、数量短语和词义，不机械按相邻字套用。同词同义同语境的有效依据可复用，但不得以复用绕过盲审隔离；盲审者可自行查询，提交结果后才接收已有查证记录。
- 本地缺少依据或存在争议时，使用 `tavily-search` 定位可靠来源，并核对规范、词典或教学资料的原文与适用语境；搜索摘要或模型生成答案不作为最终依据。网络明确被禁止时不联网。工具不可用或来源仍不足时保留待查证项，不猜测、不自动安装组件、不算通过。
- 审核与修正意见相反，或同一标注反复改回时，新建只读查证子代理，提供具体句子、争议读法和已有来源，由其核对词典及普通话规范并说明理由。禁止凭多数票或最新一次意见裁决；仍无法确定时提交用户，保留阻塞项，不继续无依据地往返修改。

### 记录与完成声明

- 每次交接绑定完整片段 ID 清单、冻结纯文本版本及当前标注稿版本（如内容哈希），避免不同稿件的检查结果混用。保留各轮审核者、全文覆盖、盲审原始结果、历史核销、修改前后标注、查证来源与理由，以及连续无问题轮次；主代理逐项核对后再放行。
- 正式记录位置遵循项目记录规则，交接中给出实际记录位置。证据中不暴露用户隐私；不得以临时检查产物冒充正式完成记录。中断恢复时先核对版本、未解决问题与已完成轮次，不能仅凭上次口头说“通过”继续。
- 完成时只声明对应版本的文本与拼音已满足上述门禁，不声称绝不会漏错或实际音频读音已验收。流程不自动授权合成、替换音频、渲染、导出、提交或关闭任务。

## 字母读音异常的局部短停顿修复

### 所有句界的默认停顿

- 后续新生成或重生成口播时，所有句界默认显式添加 20ms 短停顿：保留句末标点，在其后放置独立的 `{ "breakMs": 20 }`，由现有合成层转换为 `<break time="20ms"/>`；不能只依赖句号产生自然停顿。逐句核对实际 SSML，避免同一句界重复叠加停顿。以完整口播试听确认清楚且自然，必要时调整该句界的停顿；20ms 是默认请求值，不保证实际静音长度或必然消除连读。字幕保留自然标点，音色与语速不变，不通过后处理插入静音。本规则不自动要求重生成已有音频，临时试听不得自动替换正式素材。
- 句界连读案例：第⑦集 `242-09` 的“分别交于 H 和 K。H 的横坐标是……”在同一个 WAV 内，原口播输入 ` K。H ` 没有显式停顿；用户试听反馈句末 K 与下句开头 H 连读。后续生成遵循上述所有句界默认停顿规则，仍须整句试听确认效果；此记录不代表正式音频已修复。句界默认停顿与下述问题字母两侧的局部停顿分别判断，不机械叠加。

### 问题字母的局部停顿

- 独立字母已使用上述英文拼读标记，但整句中仍出现错读、吞音或与邻字粘连时，可优先尝试在该字母前后添加短停顿。先核对实际 SSML 和完整音频，不仅凭自动评估标记判断错读。此方法是候选修复手段，不保证对所有字母、音色和上下文有效，也不全局给正常字母添加停顿。
- 保持完整口播文字、原标点、字母拼读标记、音色和语速不变，只在问题字母两侧分别加入独立的 `{ "breakMs": 20 }` 对象，由共享合成层转换为 `<break time="20ms"/>`。可从前后各 20 毫秒开始，必要时对比少量不同停顿版本，选择整句试听确认清楚且自然的最小值；20 毫秒是已成功采用过的起点，不是通用最小值或固定答案。请求值不等于实际静音长度，原标点的自然停顿仍保留；不通过音频后处理插入静音或改变语速。
- 对比样本使用同一完整句子，仅改变局部停顿；按本文件的试听交付要求，同时展示各版完整文本和可播放音频。用户确认前保持样本独立，不替换正式素材；确认后原样复用选中的 WAV，不以相同参数重新合成来代替已确认音频。
- 采用时将局部停顿落实到独立口播输入，核对生成的 SSML 指纹与所选样本一致，并绑定音频 SHA-256。保留旧样本，基于所选音频测量或重新对齐词时间，再生成字幕时间；没有可用合成词边界时使用真实识别结果，不补造时间戳或放宽检查。仍须遵循整批发布门禁，并区分样本确认、接入暂存区和正式发布。

## 数学公式的自然口播

- 朗读公式时按数学含义表达运算层次，使用“……的和”“……的差”“……的乘积”等自然说法，不把括号符号机械读成“括号……括号”。讲解去括号、分配律或括号前负号的作用时，可以明确说“括号”。
- 加减、乘除及分式组合必须说清整体范围与先后顺序。例如 `(X+Y)+(X−Y)` 可说“X 与 Y 的和，加上 X 与 Y 的差”；除以 `b₁b₂` 应说“除以 b₁ 与 b₂ 的乘积”，不能让听众误解成先除以 b₁ 再乘 b₂。
- 复杂公式按运算层次拆句：先交代各项或各个乘积，再说明相加、相减或整体相除；不为一句读完而堆叠“乘、加、减、除”。例如先分别说明两个乘积，再说“用前一个减去后一个”；和与差作为乘数、除数或绝对值的对象时，明确它是一个整体。
- “它们的和”“这个差”等指代只在对象紧邻且明确时使用；“它们的差”还必须已明确被减数与减数的顺序。不能只靠观众看画面猜测指代、运算范围或减法次序。
- 审校覆盖本集全部口播，包括已确认的代表样例，检查同类表达；保留简单、自然且无歧义的读法，不机械把所有公式扩写为长句。按字幕先行、独立口播的流程修正，画面公式保持准确，字幕使用适合阅读的数学符号和自然标点。
- 修正须落实到受影响的正式音频、字幕时间数据及时间线，只重新合成实际改动片段，保持原速。整句试听应核对自然度、整体范围和运算次序；文本、SSML 或自动对齐检查通过不能代替试听验收。

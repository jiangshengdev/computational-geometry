# 视频制作、修复与交接

适用于仓库 `videos/` 下的视频工程；同时遵循[视频工程规则](../../../videos/AGENTS.md)。本文件管理跨阶段的依据、范围和问题闭环；具体制作方法及验收标准由各阶段文档维护，不新增授权或重复确认门禁。

## 开始与恢复工作

- 先从用户当前请求、已确认规格及决议、实际工程和素材确定本次阶段：分镜与文案、代表样例、全片扩展、局部修复或交付验收。核对已确认范例及版本、允许修改的范围、尚未解决的问题和已有检查；交接摘要只作入口，不能替代当前文件及原始确认。信息已明确时直接推进，不重新询问已决定事项。
- 已有检查按[交付规则](delivery.md#检查时机与已有结果复用)核对版本与覆盖，复用有效结果。未找到证据只说明尚未核实，不断言前人没有检查过；先查相关记录，不让用户重复提供可自行查到的事实。
- 每个阶段只交付本阶段已授权的产物。通过文案审核、样例确认或工程检查，不自动授权下一种动作；依照现有授权继续无阻塞工作，不能因一个片段待确认而停止所有独立工作，也不能把待确认项静默略过。
- 依据、问题和验证记录复用已有分镜、工程记录及项目规定的权威载体，不为每次操作创建一套平行计划。记录深度与本次范围匹配，局部修复不要求重新整理整集档案。

## 问题判定与修改范围

- 修改前说明当前版本的具体问题、违反的要求和证据，区分已核实错误、待核实疑点与可接受的不同方案。另一种读法、布局或动画成立，不足以证明当前方案错误；个人偏好与可选优化不作为必改项，不阻塞放行。
- 区分已确认范例、后续新增行为和实际缺陷。修复须同时消除缺陷并保留未受影响的内容与行为；不能通过修改范例、删掉教学过程或削弱检查使新实现看起来一致。
- 用户指出共性问题或要求全片检查时，先只读盘点该类别的全部实际实现与调用位置，明确哪些受影响、哪些已符合要求、哪些尚未核实；不能只查一个共用分支就声称已覆盖整类。盘点不自动授权修改范围外内容。
- 指定词句、镜头或配置的局部修复，只调查定位和确认影响所需的上下文；修改和验证限制在受影响范围。共享逻辑、音频时长或时间线变化确实影响其他位置时，说明依赖和失效证据后确定必要检查；不得因“更彻底”而全量重做。配音局部范围遵循[授权范围与整句试听](narration.md#授权范围与整句试听)。
- 根因说明须来自当前实现、原始操作或可复核证据。不能把未经记录的制作动机、推测或某条看似相关的提示词当作确定原因；无法确认时明确未知，不据此扩大修复。

## 问题闭环与停止条件

- 每个实际问题保留稳定定位（如片段 ID、页面、时间或文件位置）、对应版本、证据、处理状态与复核结果。修复、经证据撤回、用户明确排除和仍待处理分别记录；不能因改换分类、换聊天或只汇报本轮新增问题而丢掉旧问题。
- 已修复或撤回的问题，在相关内容、语境、规则未变且没有新反证时复用结论；新审核重复提出时先核对既有证据，不反复改回。真正的新证据仍须处理，不能用历史“通过”覆盖当前失败。
- 修改完成后检查原问题是否消除、约定保留的表现是否仍成立，以及是否产生直接相关的新问题。没有证据的“应该修好了”、检查执行完成或记录字段 `complete: true`，均不能代替问题解决。
- 当前授权范围内的交付与必要验证完成后结束，不为追求零疑点或统一风格追加新一轮优化；真实的未解决问题和范围外发现须如实区分，不夸大完成状态。

## 交接与完成汇报

- 说明当前版本、已落实产物、仍有效的检查、未解决问题及下一步入口；涉及音频时绑定实际素材与口播版本。区分稿件已改、样本已确认、正式素材已替换、工程检查通过和成片已验收，不用一个“完成”替代这些状态。
- 汇报以用户当前任务为中心，只展开影响结果或下一步的事项；详细原始检测记录保留在既有位置。音频问题展示与导出前计数分别遵循[配音检查汇报](delivery.md#完工后的全片配音检测)和[导出前音频检查](operations.md#导出前音频检查)，不混淆程序标记与实际听辨结论。

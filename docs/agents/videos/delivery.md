# 视频交付与成片验收

适用于仓库 `videos/` 下的视频工程；同时遵循 [视频工程规则](../../../videos/AGENTS.md) 中贯穿各阶段的约束。

## 完工时的工程整洁门禁

每个制作阶段正式交接前，以及每一集最终完成或交付时，必须完成对应范围的工程整理。各阶段只核对本阶段已产生的制作源、已采用素材、有效入口及其对应关系，不要求提前完成后续阶段的产物。制作过程中可以有必要的试验和临时产物；阶段交接时整理已明确废弃的试验与失效路径，仍需使用的候选、有效检查和未决请求的最小证据继续保留。整集收尾仍须核对最终工程状态，与其他已完成视频采用一致的工程质量标准。

阶段整理沿用现有删除授权边界，不因本要求自动获得删除或扩大修改范围的授权；必要确认未取得时，说明具体待整理项，不将其记作已完成。整理复用已有有效检查，只补做受影响范围的必要检查，不新增人工批准或全量重跑要求。

- 直接对照已确认参考视频的实际文件、职责划分、目录命名、制作入口与检查方式，沿用成熟组织和共享能力。本集确有教学或素材差异时保留必要差异，不照搬参考工程中的历史遗留问题，也不以文件数量相同代替质量一致。
- 正式工程只保留当前生效的教学与制作源、已采用素材、必要配置和检查，以及不可替代的最小原始证据。当前稿件、读音、请求、正式音频、实测时间与字幕必须明确对应；可从权威源生成的内容使用明确的生成入口，不平行手工维护多套版本或事实来源。必要生成物须能核对来源及当前一致性。
- 删除已废弃的试听候选、一次性诊断或迁移脚本、退役入口、失效路径、旧稿旧计划、孤立文件、无用输出及重复响应或记录。历史过程优先通过 Git 历史和权威任务记录追溯，不能以“审计”“备份”或“以后可能用到”为由保留整套试验档案。确需防止未决请求误重放或保留不可恢复原始证据时，只保留最小必要材料，并明确其职责、状态及是否参与当前制作。
- 清理必须覆盖单集目录中的实际磁盘文件，不能只删除 Git 跟踪项、增加 ignore、取消命令入口或把垃圾搬到另一个目录。正式播放与内容、音频等必要离线检查不得依赖 `out` 等临时输出、旧试验目录或重新调用语音服务；正式素材和必要时间数据须在项目内明确管理。
- 阶段交接与整集收尾时盘点实际文件和 Git 状态，沿本阶段播放、生成与检查的调用关系核对保留文件的用途，确认本阶段最新选定素材已正式接入、被替代路径已移除、没有待清理的制作垃圾。整理后仅执行受影响范围的必要检查，不删除有效证据、隐瞒未决问题或削弱检查来换取表面整洁。
- 工程整洁是对应阶段正式交接及整集最终完成的条件，不能用程序检查通过、音视频效果正常或已经提交代替。当前阶段尚有已明确废弃的文件、重复维护或失效制作路径时，不得将本阶段判为完成或正式交接；整集收尾还须清理并核验最终工程后再交付。

## 检查目标与完成证据

检查前先明确本次要证明的要求、版本和页面或片段状态，并选择能观察该要求的方法。在既有分镜、对照或任务记录中，每项对应基准位置、新版位置、实际观察状态、证据位置和结果；差异关联稳定问题标识及处理状态。静态画面、逐步揭示、对象切换、局部强调、提示结束后的内容保留、同页衔接和跨页延续分别按实际依赖核验。对字幕与口播，直接核对重要条件、普通措辞和数学含义的对应，按配音规则说明允许的表达差异；覆盖数量和时间映射只证明相应覆盖。涉及声音时，显示坐标、源采样和实际媒体播放分别记录，标明具体引擎与观察范围，不以其中一项正常核销另外两项。不能只保留截图或检查总数而失去它们证明什么的对应关系。

| 要确认的事项       | 所需证据                                                                                                                        | 不足以单独证明的结果                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 教学含义与解释完整 | 原文、分镜、画面与口播逐项对应，案例与一般论证分别核对                                                                          | 文案格式或字幕文字存在                      |
| 教学内容无重复     | 按[防重复检查与放行](../teaching-content-reuse.md#防重复检查与放行)对照旧材料具体位置、本次承接位置、新增内容及重复问题处理结果 | 类型、布局、哈希或字幕一致性检查通过        |
| 范例行为正确继承   | 实际配色、屏幕尺寸、对象选择顺序及提示起止的对照                                                                                | 复用同名组件、动画数量或截图数量            |
| 内容保持与时序正确 | 逐步揭示、同页切换、静默、思考窗及页末停留的状态                                                                                | 终态截图、总时长相等                        |
| 正式配音与稿件匹配 | 当前音频哈希、口播版本、完整识别与发音评估，按规则进行实际整句核验                                                              | SSML 正确、可解码、有词时间戳或自动评估高分 |
| 成片可交付         | 真实输出的画面、声音及同步验收                                                                                                  | 工程检查通过、导出退出成功或文件存在        |

旧版实现、修复提交及历史检查只在对应版本和适用条件仍成立时作为当前证据。修复尚未采用、效果未确认、仅作过实验、已退出当前播放路径或已被回退时，分别记录，不写成当前已解决。对已发现问题检查原偏差是否消除、约定保留的表现是否仍在、直接关联行为是否退化；证据不足时保留未核实状态。音频哈希、口播版本、实际素材、试听和成片的证据要求继续按本文件原有章节执行，不被本次对齐替代。交付用户导出命令时，在同一记录引用 [导出前音频检查](operations.md#导出前音频检查) 要求的当前覆盖与三类原始计数，并单列试听和成片状态；计数门槛仍由该章节唯一维护，不从其他精简汇报规则推导豁免。

- 声明参考继承通过或本阶段完成前，按[参考参数核对](new-video.md#新视频的参考继承)与[历史纠正带入](workflow.md#开始与恢复工作)复查当前产物。图文方向等布局要求须同时有实际调用及生效参数、对应页面的可见画面证据；确认方向不能只用组件导入、元素存在或边界不溢出代替。当前范围内仍适用的历史问题须逐项给出新版位置、证据和核销结果；存在违反要求的偏差或证据缺口时，不得将该项判为通过，也不得用其他检查通过宣称本阶段全部完成。沿用已有有效证据，仅补查缺失或失效部分，不新增逐页人工确认或无关全量检查。

- 发现问题后按[问题闭环](workflow.md#问题闭环与停止条件)处理；不能把“检测已覆盖”写成“问题已解决”。因工具或授权限制无法获得某类证据时，明确尚未验收的项目，不以另一类检查替代，也不绕过禁止渲染等边界。

## 检查时机与已有结果复用

- 先完成制作及已知问题的修复，再进行最终全片检查。仍有已知音频错误、待选择的修复样本或尚未应用的确认素材时，不提前执行最终全片配音评估、完整页面状态检查或整套预检；不得为阶段汇报、提交或“保险起见”反复重跑。
- 制作和修复过程中，只执行定位问题、生成可试听样本及确认修复所必需的局部检查。不能因为最终全片检查尚未执行，就跳过当前修复必需的文案、SSML、音频格式、解码、识别对齐或时间数据校验。首次发现未知问题所需的检测，按缺失覆盖选择范围，不以“先修完”为由无限推迟。
- 收尾前先核对已有检查记录，包括相关历史对话、交接、日志和产物，而不只依据当前对话或 README。逐项确认检查类型、覆盖片段及页面状态、对应源码或素材版本、音频哈希与口播指纹；缺少证据只能表述为“尚未核实”，不得断言其他对话没有检查过或本轮是首次检查。
- 全片覆盖不等于每轮全量重跑。复用当前版本仍有效的结果，只补齐缺失或因变更失效的部分。仅修复个别音频时，重新检查受影响音频及其词时间、字幕、镜头同步、动画和相邻衔接；时长变化还须核对后续时间偏移、页面停留与总时长，不因此重新识别其他未变音频或重跑全部页面。
- 只有共享逻辑或其他变更确实扩大影响范围时，才相应扩大检查；执行前说明哪些既有结果失效及原因。最终全片检查发现新问题后，先修复，再检查受影响部分，保留其他仍有效的结果。
- 报告须明确是哪项检查、覆盖哪个版本及范围。类型、解码、时间线或页面状态通过不代表实际读音正确，自动评估不替代整句试听；不得笼统用“全部检查通过”掩盖待试听或成片验收事项。

## 内容与素材交付闭环

- 按[教学内容呈现](../../../videos/AGENTS.md#教学内容呈现)对本次视频全部片段双向核对画面与口播，覆盖首次引入、逐步推导、本页保留和跨页引用。允许表达不同，数学含义与必要解释必须完整对应；列出缺少讲解的重要新对象、符号、条件、关系或推导及所缺解释，不能仅凭字幕与口播一致判定完整。
- 按[时间线规则](timeline.md#音频与时间线)核对整行显示与开口顺序，分别检查未讲内容被当作已知依据及思考窗口泄露答案。新增解释须核对正式音频、字幕和时间数据版本一致；检查结果与实际整句试听的区别遵循[验收声明边界](../../../videos/AGENTS.md#验收声明边界)。
- 对左侧无其他内容、正文先居中后平滑左移的页面，核对居中状态、移动前后及过程中、右侧内容出现时的画面，确认已讲内容保留、块内对齐稳定且无遮挡或突跳。
- 逐句检查完整字幕的标点和语意连贯性，并对照口播确认两者独立断句。若全片字幕没有中文逗号，或出现“为看清两点。”一类依附后文的片段却以句号结束，必须回查字幕原稿，按语义修正或说明合理原因；不得仅凭文案校验、字幕生成成功或与口播分句数量一致判定通过，也不得机械补逗号或设定逗号数量指标。
- 分别核实文本、实际发音和时间数据。解码成功、词时间戳存在不证明读音正确；时间数据异常也不直接证明声音缺失。
- 用户认可的配音修正须落实到正式素材及对应时间数据。交付时明确区分“稿件已改”“样本已确认”“正式素材已更新”和“整集已验收”；中断时报告准确停点。
- 以上检查继续遵守禁止助手渲染视频等现有边界，未完成的验收如实记录。

## 完工后的全片配音检测

- 每个视频制作完成后、交付或声明完工前，必须以独立口播稿为参考，确保全部正式配音片段的实际音频均有匹配当前版本的逐段语音识别与发音评估结果，检查漏读、插入及发音异常；按上文复用有效结果、补齐缺失覆盖。已确认的代表样例也须覆盖，不得抽样或仅在字词时间戳为零时触发。文本完整、合成成功、音频可解码或存在非零时间戳，均不能替代此项检测。
- 检测须绑定当前音频的 SHA-256 和对应口播稿，保留逐段原始服务响应及汇总，记录总段数、已检测段数、无异常段数、异常位置和请求失败。缺失结果、请求失败或素材与检测记录不匹配时，不得声明全片检测通过。
- `Omission`、`Insertion` 与 `Mispronunciation` 在检测记录中分别保留，并结合实际整句音频复核，不将模型标记直接等同于已确认的漏读或错读。
- 一般配音检查汇报只展开已核实的严重问题：明显影响可懂性、改变数学或教学含义的错读、漏读、插入，以及音频缺失、损坏或严重音画错位。不逐项罗列未确认的自动评估疑点、低分字词或轻微自然度问题。但凡列出问题音频供用户试听或核实，必须按[试听交付要求](narration.md#授权范围与整句试听)，在音频旁同时指出具体问题位置、应读内容、问题类型及确认状态；不得以“尚未确认”为由省略需要用户核实的位置。尚未完成复核时说明验收状态，不能宣称读音已通过；完整检测记录仍须保留，不降低检查覆盖或隐藏失败。导出前必须另外按[导出前音频检查](operations.md#导出前音频检查)分别报告三类程序标记的条数及阻断结果，不将这些计数称为已听辨确认的错误数量。用户明确要求检测统计时也按请求提供，不能以精简汇报隐藏结果。自动检测无异常不能替代整句试听及成片音画同步验收。
- 修正配音后，必须对更新后的正式音频重新执行检测并同步核对时间数据；其他音频和口播稿均未变化且已有有效结果的片段无需重复检测。该要求不授权助手渲染或导出视频，也不授权自动修复配音。

## 成片验收

- 发布或关闭任务前，须按该视频的权威规格检查真实成片，完整试听中文可懂性、坐标、字母、公式、自然度与同步，并核对思考窗口。

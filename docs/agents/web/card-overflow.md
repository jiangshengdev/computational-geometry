# 卡片边缘与滚动容器

- 新增、迁移或修改卡片布局时，检查从卡片到外层布局的裁剪链，包括 `overflow: auto/scroll/hidden/clip`。卡片边框、阴影和焦点环可能绘制在盒子外；内容未溢出不代表边缘未被裁剪。
- 卡片内容需要滚动时，优先复用现有内容区滚动规则，不得在紧贴卡片边缘的外层重复添加 `overflow-auto`。当前 `.workspace-panel [data-slot="card-content"]` 已提供内容滚动；新增外层滚动必须有独立的内容可达性需求。
- 多张卡片必须整体滚动时，为卡片外部绘制留出空间，并逐层检查内部包装元素是否仍在裁剪。沿用已有的负 margin 配合等量 padding 扩展滚动区域的方法；当前 `.hull-learning-stacks` 使用 `margin: -8px; padding: 8px`。该值是现有组件的实现参考，不是适用于所有阴影或焦点环的固定保证。
- 不得通过去掉阴影、隐藏边框、禁用焦点环或取消必要滚动掩盖裁剪。保留卡片位置和布局间距，确保长内容及末尾卡片仍可到达。新增同类页面须检查并复用已有处理，不能只复制组件而遗漏其容器约束。
- 修复或调整相关布局后，按 [前端测试与滚动验证规则](testing.md) 验证内容可达性和滚动行为；不新增锁定外观的自动化断言或截图快照。边缘裁剪需结合实际浏览器渲染检查，不能仅以类型检查、构建或功能测试通过宣称视觉问题已解决；未执行的可见 Safari 验收须明确说明。

# 滚动与联动定位

## 区分高亮与定位的触发原因

- 列表内部的 hover 进入、切换和离开只更新联动高亮，不得触发回到当前教学步骤、选中项或默认位置的自动滚动。鼠标不动时，滚动经过不同行也会产生 hover 变化，不能把这些变化当作新的定位意图。
- 教学步骤变化、画布定位和用户手动浏览分别处理：步骤实际变化时定位该步骤的目标；画布交互按既有功能定位对应列表项；同一步内手动浏览应保留滚动位置。
- 自动定位的触发依赖必须与定位目标的来源一致。禁止将通用 `active` / hover 对象作为步骤定位 effect 的触发依赖，同时在非画布交互或 hover 清空时回退到 `step.current`。高亮对象变化和组件重新渲染本身不构成定位请求。
- hover 结束不得自动恢复先前的步骤位置。联动须识别事件来源，防止“画布定位列表 → 列表在指针下移动 → hover 改变 → 再次定位”的反馈循环。

## 实现与回归

- 优先复用项目已有的滚动定位能力，在调用方明确区分触发来源；不要复制滚动算法。检查同类调用方，但仅修正具有相同触发问题的路径。
- 不得通过永久禁用 hover、移除必要的画布联动或步骤定位、延时掩盖回跳来修复问题。
- 验证遵循 [前端测试与滚动验证规则](testing.md)。滚动是否可继续、目标是否可达属于功能验证；不要将具体像素位置写成跨环境固定预期。
